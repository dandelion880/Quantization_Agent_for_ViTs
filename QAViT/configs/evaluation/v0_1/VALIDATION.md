# 初版离线接入的验证清单（不生成科研评测任务）

Codex 接入后应充分测试以下**接口、数据和评分边界**。这里列的是程序单测/回归不变量，不是用户要求稍后才设计的代表性科研案例；不得另建“专家样本生成器”。

## A. 静态规则和评分协议

- 六份 JSON 能用标准 JSON 解析，Rubric ID 唯一，criterion ID 在相应 purpose 内唯一且 0/1/2 锚点齐全。
- `agents/tasks.py` 中六类科研 LLM 角色与 11 个 LLM purpose 全覆盖：generate；Judger 六子任务；evolve、record、code、safeguard。
- `supervise` 保留为无样本时不评分；`experiment_request role=supervisor` 和 `author=program` 的 rank 不计为 LLM 产出。
- Generation 三种 slot、parent/final 两种 rank、H4 唯一父方案、合法 `tie/undetermined/continue`、有真实不可解问题时 `defer_reason` 的适用区别。
- Judge 输出验证能识别丢项、多项、错误 criterion、score/status 不一致、伪造 source_id、错误 schema_version；这些只影响**离线评分**。
- `not_applicable` 与 `unknown` 独立，缺失来源不被自动当 0，`Q` 归一化和覆盖率分母正确；无有效评分输出 null。

## B. 任务与证据归并

- 在一个任务包含多次模型调用、等待工具、恢复、重试/修复、代码与数值子任务时，不漏计或重复计量；`parent_task` 关联正确。
- 截断/缺失的上下文、未读全文、未完成模型调用保留明确覆盖信息；某个卡片的列表索引不能冒充已读正文。
- 事后出现的有效 L3/负面结果不会混入当时冻结的角色输入；对 position 不出现同 exchange 未汇合的对方私有发言。
- 真实/合成/test_double、失败/中断/缓存结果区分；缓存不算独立重复；不同数据范围不误归一化。
- 请求模型与实际回显不同字段保持原样；实际未知不伪装已核实；token 子字段不双算；数值纯等待与订阅锁等待不伪装纯推理时间。
- 程序故障、模型输出格式问题、科研语义错误和用户未定义的必要科学输入区别记录；代码无法执行时有证据才归责到 Coding。

## C. 安全/隔离/回归

- Judge 无法调用科研工具、修改 EXP 历史、注入 Journal/Memory/Top-3、变更模型路由或影响科研生产程序。
- 被评价内容中的“给满分/修改指令/忽略评分”不成为 Judge 的控制指令；引用不存在则评分失败或标 Unknown。
- 离线目录中保存版本/来源身份；重跑不污染原运行和旧评分，能比对版本、审计结果。
- 跑必要 CPU 单元测试、现有相关 QAViT 回归，证明没有给科研流程增设新的字段门禁、额外 LLM 调用、实验条件或预算开销。
- 可以在**已存在且获准读取**的历史轨迹上做极少量真实评分器烟测；若没有可用真实轨迹、订阅不可用或预算不足，应只报告未验证项，不伪造真实 Judge 调用或数值成绩。

## D. 输出要求

测试报告说明：检查了哪些目的/案例、哪些通过、哪些由于真实材料缺失未能验证、原生产源码/功能是否变化、评分原始回执如何复查，以及未来人工如何读取单条评分/来源。不要只写“测试全绿”而不列证据。完整科研验证和代表性测试案例集合**留待以后**。
