# 给 Codex 的接入提示词

请在当前最新版 QAViT 仓库中，独立接入 **Eval-L0 的六类科研 LLM 离线评分系统**。先阅读当前 `AGENTS.md`、真实角色/任务映射、科研流程、日志/卡片/实验回执、以及本轮文件结构规则，并在 `projects/` 中定位我上传的 `QAViT_Eval_L0_Rubrics_v0_1.zip`，完整阅读其中 `README`、原则、六份 Rubric、Judge Prompt、输出 Schema、接入说明和验证清单。以压缩包评分规则为本版权威内容，正确放到与现有职责相符的静态资料位置，避免双份副本。

实现一个**完全独立于生产科研主流程**的只读评价入口：按 run → role/purpose/task → 全部真实 LLM 调用/工具与实验 → 产出及证据，生成可追溯样本；程序统计 Token、时间、重试、调用与既有执行状态；独立 LLM Judge 按对应 Rubric 输出 0/1/2、N/A/Unknown、证据指针、理由与置信度；程序验证评分输出、计算归一化科研质量与覆盖率、生成分角色/子任务的 JSON 和可读报告。评分器暂定 **`gpt-6.1-sol`、`medium`**，其调用与成本单独记账，不加入生产 Judger 或生产队列。人工抽样和代表性科研测试任务之后由我负责，本轮**不做抽样生成器、样本集或额外评审交互**。

核心要求：以真实源码为准做最小且配套的新增；不改变任何已经跑通的科研角色 Prompt、研究任务/合同、Judger 辩论、Generation/Evolution 循环、Coding/Safeguard、Recorder/Memory/Skill/Method、预算/GPU、证据晋升和恢复语义；**绝不把评价分数、Judge 或新字段加入科研运行门禁**。严格区分 Judger 六 purpose、自动程序 rank、supervisor 程序身份、先后可见信息、缓存/真实数值、合法未决和局部实验；若日志/数值/源码不足，用 Unknown，不猜测成绩或因果收益。质量与成本分开展示，角色任务间不强行平均。

目录遵守最新结构规则（静态规则/Prompt 在 `docs/evaluation/`、独立工具可在 `tools/evaluation/`、测试在 `tests/evaluation/`、评价产物在独立 `EXP/evaluations/`，实际按仓库情况合理调整），并保持版本与来源可追溯。充分开展离线 Schema/角色映射/证据来源/缺失信息/时间边界/成本归并/安全隔离/回归测试；条件允许时对**已有真实轨迹**做小规模 Judge 烟测，不能伪造真实分数或开展新的 GPU 科研实验。出现非评价模块故障时不随意扩张重构。

完成后交付实现清单、真实验证结果、尚不可评分的边界、调用示例与数据存放路径，并核验评分规范已完整接入。**只有确认已解压、所需文件保存正确、全部必要测试完成后，才删除 `projects/` 中本次上传的那一个原始 ZIP 文件**；保留已接入的评分资源、报告和用户其他文件，不使用宽泛删除命令。
