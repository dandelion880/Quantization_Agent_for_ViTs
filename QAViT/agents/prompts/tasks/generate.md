# 本次任务：生成一个初始假设

## 输入与工作

从 context.task 确认本次槽位和探索类型，固定身份由程序绑定，不生成其他槽位。阅读 ResearchBrief、当前绑定的相关记忆和前轮反馈；长字段按 required_reads 按需读取，其余历史通过目录按需获取。

围绕当前槽位形成一个主张清楚的候选。写明干预、作用机制、适用条件和最重要的替代解释；必要时用公式说明。有明确预测时说明可反驳它的结果，按需设计能区分关键解释的对照。缺少支持性实测可以明确保留为待检验，不能伪造成既有发现。

只有前置取证会实质改变机制定义、与已有工作的关系或验证设计时，才继续取证。机制可解释、实现可描述、研究含义可检验、已用来源状态清楚后，提交本卡片，不以完成全部验证作为生成阶段的前提。

## 提交正文

提交 HypothesisCard 的 payload，按 payload_contract 提供科学字段；宿主补固定身份：

- title：非空字符串，准确概括干预。
- research_question：非空字符串，说明当前要解决的具体问题。
- mechanism：非空字符串，说明前提、机制链、关键数学关系及替代解释。
- intervention：对象或字符串，明确改变什么、保持什么，以及核心算法。
- predictions：可选数组，可为空。每项提供 statement；有明确设计时补充 measurement、falsification，分别说明比较范围和反驳条件。id 由程序编号。
- implementation：可选对象或字符串，说明现有能力、需要新增的能力及实现接口方向；区分已实现与计划实现。
- validation_design：可选对象或字符串，说明优先检验、控制变量、竞争解释、结果分支与决策影响；拟采用的数值阈值必须标明是预先选择的判据，不能伪装成实测。
- sources：可选对象数组，可为空。每项写清真实来源、阅读或核实状态及它支撑的内容。可使用已读文献、现有卡片或明确标记的理论分析，不为满足数组要求编造论文。
- evidence_refs：可选数组，只列本次实际用于形成判断的 EvidenceCard 短句柄或完整 ID；sources 的 ref 也可绑定实际使用的卡片。程序归档全部实验，不能把“已归档”当作“支持本假设”。
- mechanism_relations：可选数组，每项含 relation、target、explanation 三个非空字符串；说明与实际已知方法或假设的机制关系，无可确认关系时省略或为 []。
- feedback_used：可选对象数组。需要说明采用或质疑反馈时表达其具体影响；唯一绑定的 metareview_ref 由程序补齐。存在历史反馈不意味着必须改变方案或填写采纳说明。
- scope：可选对象，记录选择的研究范围、条件和外推边界，区分计划研究范围与已经验证的范围。

不要创建卡片封套，也不要把待执行实验写成 EvidenceCard。

H1/H2 使用 context.complete_solutions，按需 read_asset 读取 configuration_asset 和方法卡，自然说明选择的完整基础方案及保留/修改内容。三者共享 Brief 与按需 Memory，H3 仍独立探索新机制。
