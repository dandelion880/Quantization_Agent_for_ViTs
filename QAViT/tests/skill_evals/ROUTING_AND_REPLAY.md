# QAViT Scientific Skills v0.3 — 离线触发与研究策略试验集

**用途**：保留原包可人工编辑的研究情境、预期策略和反例；不是运行时路由器、模型验收门禁或已经完成的实测结果。本文件是**测试设计**；本次源码接入与实际已执行范围见 [验证报告](../../../EXP/validation/scientific_skills_20261108_r1/REPORT.md)，不能把全部案例视为已完成。

## 评什么

对科学 Skill 的评价应先判断“被正确使用了吗”，再判断“使用后科研判断是否更好”。避免只考察是否出现某个关键词、是否读满所有参考材料或是否输出了标准表格。

建议 L0 两条件对照：

- **无 Skill**：给同样的 ResearchBrief、明确的 Evidence 和可用工具说明，让当前角色自然推理。
- **有 Skill**：仅额外开放 `docs/skills/INDEX.md` 与按需读取的 `SKILL.md`/`references/`；保持模型、随机性约定、角色、证据、预算、工具能力尽量一致。
- 对每条输入记录：是否选择合适 Skill（包括正确地**不使用**）、是否提出与证据匹配的科学解释、最有信息价值的对照/方案/下一步、推断边界、冗余工具或实验请求、额外 Token/时间成本。
- 判读由研究者与可选择的第二评审独立阅读盲化输出完成；即使内容看起来“专业”，只要实验不可区分解释或夸大证据，也应判为弱。

不需要为测评本身增加 QAViT 正式流程中的审核阶段。L1 只选择 L0 明确有收益且能低成本复现实验的少数案例。

## A. 定位问题：该用与不该用

| ID | 给研究者的具体情境 | 期望 | 应避免 |
| --- | --- | --- | --- |
| A1 | 同一 W4A4 任务中 W-only 接近 FP、joint 明显退化，尚无相同前缀 A-only。问“根因是什么？” | **A**；建议找可比的 A-only、joint 与冻结前缀证据，把激活与耦合都列为候选 | 直接宣称就是激活 outlier，或转入全层无目标 profiling |
| A2 | DINOv3 某层 storage token 幅值明显高于 patch，任务跌点明显，但没有量化误差分解。问“是不是 storage 导致？” | **A**；用分 token 能量、量化误差、干预与传播区分相关与因果；并考虑其他 token、channel 与 LayerScale | 以 raw q99.9 一项数据宣布因果 |
| A3 | 当前 FP 参考比过去干净 FP baseline 低约 2pp，同时量化结果也异常。问“怎么解释退化？” | **A**；先核对评测口径、模型/头、版本、输入、量化覆盖；无需全量重复 profiling | 在参考未可信时进行算法排名 |
| A4 | 代码运行时抛出明确 `shape mismatch`，已定位维度写错；问“怎么修复？” | **无需科研 Skill**；交回常规 Coding 流程 | 为工程错误启动 W/A 敏感性分析 |

| ID | 给研究者的具体情境 | 期望 | 应避免 |
| --- | --- | --- | --- |

| C2 | 局部重构指标很好，随着量化前缀增长，预测误差不断放大。 | **C**；借鉴 GPTAQ 区分真实量化输入与 FP 目标，冻结前缀对比；明确哪个参考衡量成功 | 用 FP 输入校准获得好误差后声称解决真实前缀失配 |

| C5 | 现有成熟方案准备直接在相同模型上做忠实复现，机制和实现已确定。 | **无需科研 Skill**；按既定实验路径执行 | 为体现创新强行添加模块 |

## D. 解释证据与下一步决策：该用与不该用

| ID | 给研究者的具体情境 | 期望 | 应避免 |
| --- | --- | --- | --- |
| D1 | 某 AV 局部干预同冻结 peer SSE 下降 5%，同 FP 目标 SSE 下降 1%，缺少后续证据。 | **D**；明确两个参考的结论范围，建议依机制选 holdout/后续 logits，拒绝把局部改善等同分类精度 | 把 5% 写成 Top-1 +5pp |
| D2 | QPF 三个分支在某次冻结 ADE20K 上差距很小，但采用了不同自由度/训练细节，尚未保证完全可比。 | **D**（必要时 B）；优先核对结果可比性和额外自由度，再判断是否值得扩成整网 L3 | 用小差距直接宣称某个子机制有效或无效 |
| D3 | W4A4 在 ImageNet10k 相对基线接近，但 ADE 冻结分割效果较差，问“是不是泛化成功？” | **D**；承认两个任务各自证据，指出跨任务尚需验证；可回到 A 查 task-specific 误差 | 以一个数据集上的 top-1 推出另一个任务 mIoU |
| D4 | fake-quant W4A4 在 FP GEMM 上 profiling 延迟变好，想宣布 INT4 推理加速。 | **D**；指出推理精度/内核与部署测量缺失，提出真实低比特推理的下一步 | 用理论 bit 宽或 fake-quant wall time 作为实际 INT4 加速 |
| D5 | 一个候选已经完整评测，研究结论明确，Recorder 只需按既定机制保存原始记录。 | **无需科研 Skill** | 强制再发一个“研究价值评估”回合 |

## E. 边界与组合

| ID | 情境 | 合理行为 |
| --- | --- | --- |
| X1 | 观察到误差异常，但证据已足以定位为校准 grid 问题，马上需要有根据的修复 | 可直接 **C**；不强制重走 A |
| X2 | 有两种对 outlier 的解释，又已设计了最小对照，并已得到清晰反证 | 可直接 **D** 或继续研究；不必读 B 只为补形式 |
| X3 | 普通实验进展顺利，研究者根据已有 Evidence 提出 H2 并送原 Coding 路径 | 可以**零 Skill**；不影响正常执行与结果返回 |
| X4 | 某个负结果来自 GPU OOM/预算耗尽，未产生可比较的数值证据 | 不当成科学反证；可以先解决工程/预算，必要时 **D** 只讨论投入价值 |
| X5 | 竞争解释消除后，研究者同时想提出 W/A 补偿方案并问是否该正式 L3 | 可先 **C** 再按需 **D**；按当前信息量最省的路线选择，不规定调用顺序 |

## 三个较深入的人工回放示例

### 1. “storage token 大”究竟证明了什么？（A→可选 B）

输入：DINOv3 中 block2 某 storage token 的 high-percentile 幅值远高于 patch，局部 W4A4 指标差。研究者怀疑是 storage 异常值导致性能下降。

高质量研究行为：先指出 raw 幅值不是量化误差；检查该位置的能量、实际 A4 截断/量化误差与对后续表示的贡献，比较 patch/CLS/其他高敏感通道。若需要，做定点旁路或分 token scale 干预并冻结其他量化器，观察下游变化。如果旁路使后续误差恶化，应修订假说。**不得因幅值高就将其视为无需验证的根因。**

### 2. “W4A32 好、W4A4 差”是否应该直接上复杂方法？（A→B→C 可跳步）

输入：重量化基线强，但 joint W4A4 明显退化。历史 Memory 里不同数据集有多种 A4 试验；它们的分割协议/校准量可能不一致。

高质量研究行为：先筛选相同父方案、相同任务与数据协议的 W-only/A-only/joint；如果不存在，不把历史跨协议差值相减作因果结论。可能的解释包括激活网格、W/A 耦合、实际量化前缀失配。只补能够改变“该用哪种修复机制”的对照。结果支持耦合时可沿 ERQ 类路径设计候选；若是特殊激活分布，参考 PTQ4ViT/RepQ；若主要是前缀累积，考虑 GPTAQ 思路。**不会预先固定一种 SOTA 胜出。**

### 3. “局部收益 5%”值不值得耗数小时完整评测？（D）

输入：同 peer 局部 SSE -5%、同 FP SSE -1%，已耗费多轮 calibration，还没有独立 holdout 或 logits 结果；完整分类评测代价很高。

高质量研究行为：确认两个 SSE 的分母、目标与前缀一致；确定下一步最重要的未决问题是泛化还是传播。如果既无独立 holdout 又无传播证据，可以先选择其中更便宜、预测更有区分力的一项。如果下游已可信且整个候选合规，也可直接 L3。若实验预期无论正负都无法改变判断，可停止。**不是机械地要求“先跑完所有局部项目”，也不是无条件升级。**

## 建议评分（供人工调优，不作为运行时门禁）

每个输出独立按 0/1/2 计分：

1. **情境判断**：触发/不触发及 Skill 数量是否合宜（0 错误；1 勉强；2 准确）。
2. **机制推理**：是否指出假设与竞争解释的可观察差异（0 猜测当事实；1 有方向但含糊；2 清晰且可证伪）。
3. **实验信息价值**：所选证据是否可能改变判断、是否合理控制混杂（0 无意义；1 部分有效；2 高判别力）。
4. **证据边界**：比较参考、前缀、数据划分、合规与部署主张是否准确（0 过度外推；1 有少量混淆；2 准确）。
5. **成本与自主性**：是否避免冗余查询、新门禁、无效实验与固定顺序（0 严重浪费；1 部分冗余；2 精简灵活）。

再单独记录 `token/time/GPU`、非必要工具调用数和真实 L1 改善情况，防止一个“很会讲故事”的 Skill 因长度大幅增加成本，反而降低净科研产出。

优先修订**具体策略文件和触发 description**，不因某个失败用例就增加越来越严格的 JSON 校验或禁止自由推理。少数成熟高价值原则可沉入通用 Skill；某个方法的细枝末节仍留在 `docs/methods/`。
