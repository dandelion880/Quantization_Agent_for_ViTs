## H-ViT

<a id="h-vit"></a>

**证据。** 综述 [45]；[Autonomous Intelligent Systems 正式全文](https://link.springer.com/article/10.1007/s43684-025-00121-0)，§3.2、Algorithm 1、§4.1–4.6；发表于 2025-12-23。已读全文；未核实作者代码。不要与医学配准中同名 H-ViT 混淆。

### 第一层：原配方

以硬件较简单的对称均匀量化和 per-layer W/A 为主体，校准时比较相邻 PoT scale 的重构误差，而非直接四舍五入 scale；再搜索合适的激活最大值以控制离群值。LN 输入先按通道 PoT 量化，提取共同二次幂因子，通过整数移位转换到统一尺度以计算统计量；LN 输出采用 token-wise 量化。参数来自校准统计与离散搜索，不做模型训练。

分类校准 **32 图**、COCO 检测/实例分割 **1 图**；主要格式为 **W8/A8/attention4**。这不是固定全 A4。原文称其局部 PoT 设计无需额外超参数，仍需保存 bit、校准数据与舍入规则。注意论文把其 Power-of-Two Quantization 模块也缩写为 PTQ，登记时应展开名字以免与 post-training quantization 混淆。

**原文量化边界疑点。** 正式 PDF 第 6 页 Eq.(18) 把 clip 区间印为 `[-2^(b−1)−1, 2^(b−1)−1]`；若按整数闭区间解释，含 `2^b+1` 个码态，4 bit 时为 17 个。因此不能逐字复制为合法的 b bit 码本。目前未核实作者代码或勘误如何处理该边界；实现前应锁定编码约定，并把自行修正明确登记为适配，不能一面更改公式、一面声称完全忠实复现。

### 第二层：primitive

PoT 二候选比较、迭代裁剪、LN 通道尺度统一与 token-wise 输出量化可拆开。与已有 PTF 的区别须通过公式和输出确认，不能因同为二次幂就宣称未实现或完全等价。真实部署还需区分静态 scale 与 token 输入相关 scale；最后一种行为可能超出严格静态主线。

### 第三层：workflow

原文有组件消融、校准时间比较，并在 Versal AIE 上测试固定调度下改变 scale 格式。QAViT 可在相同校准源和量化 granularity 下先比较 H-ViT/P2 的 scale 选择，再分开研究减少 per-channel 参数带来的存储和精度变化。若将 8 bit 主体降到 4 bit，或把 token-wise 输出冻结为静态尺度，必须以变体名报告。

**协议与差距。** 完整原法进入 integer/mixed-granularity 扩展；固定 bit 主线可调用其中的 scale 搜索，但不能把原精度成绩搬入。现有动态 token 容器可复用，需补 PoT 校准原算法、导出尺度约定和真实后端验证。


## 接入依据与来源边界

**基线组件** PTF/PoT、integer LN、token 表示基础。

**配方阶段与依赖** 补相邻 PoT 误差比较、裁剪搜索、LN 通道尺度统一与 token 输出参数。

**部署条件** 原 W8A8/Attn4；输出尺度是否输入相关须据实际实现判断，固定 A4 是适配。

**尚需核对** Eq.(18) 印刷上下界有 2^b+1 码态；作者代码/勘误未核，禁止照抄成“真四位”。
