## 11. IGQ-ViT：量化器固定，但分配规则在运行时执行

<a id="igq_vit"></a>

**证据。** 综述 [70]；[原文 v1](https://arxiv.org/html/2404.00928v1)，CVPR 2024，§3.2–3.3、Algorithm 1、附录 A.1–A.3；[作者项目页](https://cvlab.yonsei.ac.kr/projects/IGQ-ViT/)。已读方法和补充；本次未核实独立官方完整执行仓库，第三方平台不能自动视为作者实现。

### 原配方

IGQ 为 Linear 输入通道建立多个量化器，以通道 min/max 与候选范围的距离分组，交替更新分组和范围；Softmax 则按 attention 行的最大值分组。校准后各量化器参数固定，测试时重新依据输入范围分配组。组数按层分配，在 BOP 预算内最小化模型输出扰动；候选组数 `{4,6,8,10,12,16}`，用整数规划求解。附录设置为 300 次交替更新，每 75 次重新分配组数；分类 32 图、检测/实例分割 1 图。[原文 §3 与附录 A](https://arxiv.org/html/2404.00928v1)

不同组结果需要缩放后求和，原文成本包含 min/max、分组与 FP sum。检测的扰动量也不是纯分类 KL，而合并了类别、框和 mask 差异，部分项使用 ground-truth 类别索引；不能直接将其包装为完全无标签的通用双任务指标。

### primitive 与精确语义

`group.instance_range_assignment` 的输入为该实例通道/attention 行范围及固定中心，输出非连续组索引；`search.group_count_budget` 接受每层候选的任务扰动和真实成本，输出组数配置；`reduce.group_scaled_sum` 记录缩放与累加精度。QAViT 的现有 per_group 通常是固定相邻分块，不能代替 IGQ 的按输入分配。

原文式 (4) 的 min/max 与 u/l 下标方向和紧随的 upper/lower 文字定义看起来不一致，执行时应核对正式 PDF或作者实现；数据结构使用明确的 `lower_bound/upper_bound`，不要靠 u/l 字母猜含义。这个局部歧义不抹去已明确的动态分配与预算算法，但原式候选和修正候选不能静默混合。

### 研究工作流与配置归属

原配方进入动态分组 profile，即使 scale 固定也不满足“分组固定”的 static 定义。把校准分组冻结后可以建立 `igq_static_partition_adapted`，但它是需要重新验证的适配。拟议 `study.partition_drift` 量化同一通道在不同图像、crop 和任务间的组分配变化，再判断静态冻结损失是否值得换取部署简化。预算搜索必须同时报告组索引、gather/scatter 与缩放累加成本，BOP 不能当作实测延迟。真正值得借鉴的研究逻辑是“输入异质性决定分组，并把分组预算交给任务扰动”，而不是简单增加 group_size 候选。


## 接入依据与来源边界

**基线组件** 范围统计、分组容器、任务输出误差与成本记录。

**配方阶段与依赖** 补实例 min/max 分组、固定量化器交替拟合、组数 ILP、非连续 gather 与分组缩放求和。

**部署条件** 原法按输入重分组，属于动态；冻结组是新静态适配，不能用固定相邻 group_size 代替。

**尚需核对** upper/lower 式号歧义及作者完整代码未闭合；检测扰动部分用标签索引，运行分组/求和成本不能省。
