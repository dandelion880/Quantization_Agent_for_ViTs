# 评估量化候选并决定下一步投入

判断已有证据究竟支持什么，再选择有价值的后续行动。服务于 Generation 的候选研究、横向综合修订与各候选 L3 规划，也供 Recorder 复盘参考。复用现有工具和记忆；不增加审批角色、固定实验次数、必读列表或性能门槛。

## 从待判断的主张出发

先确定当前需要判断的是哪一件事：局部机制是否存在、干预是否改善当前完整方案、值得不值得再测、能否进入 L3，或能否迁移到新模型/任务。已有候选与尚未实现的设想采用不同表述：未执行的方案可以有明确机制与可检验预测，不能被评价成已取得或已失去数值收益。

恢复影响判断的最少上下文：候选和对照的确切版本、原预测、数据用途、实际干预范围、冻结背景、已执行测量及未完成事项。需要关键数字或争议事实时回到原始 Evidence；摘要、文献、Skill 示例和旧 Recorder 判断均不能替代本次测量。

比较候选与 B 时使用**本次选择前的 B**。候选后来晋升为当前 B，不表示本轮没有新方案或新执行。历史相邻方案差值可以描述实际进展；没有同期配对消融时，保留各改动、数据与实现差异，避免将全部收益归给一个机制。

## 分开回答四个问题

| 问题 | 主要依据 | 判断边界 |
| --- | --- | --- |
| 是否实际测到了所声称的东西？ | 实际样本、执行状态、模型与参数、干预、参考输出、回执 | 工具拒绝、加载失败、超时和未执行不构成机制反证；synthetic 结果只覆盖其合成情境 |
| 结果对机制说明了什么？ | 预先可区分的预测、适当对照、替代解释、反证 | 同一次试验的多个指标或处理臂不是独立重复；输出变好本身不证明因果解释 |
| 对当前任务有何价值？ | 同一条件下的下游表征、任务代理、完整协议结果与成本 | 局部误差、整网输出、Top-1、mIoU 和真实部署速度分别报告 |
| 能否迁移或继续投入？ | 与目标情境相符的条件、未参与选参的证据、后续成本 | 同协议不等于同背景；已验证方案不等于已验证通用规律 |

按疑点阅读 [证据范围与指标核对](references/evidence-and-comparison.md)。若涉及轻量 STE、尺度拟合 oracle、冻结迁移或反复使用验证集，阅读 [从探索 oracle 到正式候选](references/oracle-transfer-and-selection.md)。无需逐项补测；已有足够证据时直接判断。

## 解释一致结果与冲突结果

- **局部误差下降，下游也改善**：判断干预是否仍完整、代价是否可接受，再考虑直接 L3 或少量必要验证。保持“机制得到支持”和“正式任务收益尚待测量”的区别。
- **局部下降，下游恶化或无变化**：检查参考是 FP 输入还是 Q 输入、目标是否覆盖关键 token、误差传播与交叉项、校准选择是否过拟合。决定问题是目标选择、拟合时机还是机制本身。需要改变拟合目标时转入校准目标选择 Skill；需要区分两个解释时转入 `design-discriminative-experiment`。
- **不同任务方向相反**：保留成对任务指标、单位及 FP 参照，按当前 Brief 的任务排序评价候选；同时分析 CLS/patch、表征与 head 的可能差异。不因一个指标有利而隐去另一个。
- **有效实验为零增益或负增益**：缩小机制主张，检查实验是否有分辨力及干预是否实质改变了实际码器；若已排除关键解释，可停止。不要默认需要更多搜索，也不要把无收益一概归因于工程。
- **少样本任务指标相同**：先确认离散指标是否只能产生粗粒度跳变，以及候选预测是否实际不同。同分可支持“本次样本未区分”，不能直接证明算法等价或普遍无效。
- **多个因素同时改变**：完整候选可能有价值；先如实评价组合结果。仅在归因会改变研究决策或发表主张时追加必要消融，避免为了形式拆解所有组件。

比较代理指标是对当前证据含义的判断。选择、重新设计或拟合一个代理目标属于校准目标选择工作；制定针对替代解释的对照属于判别性实验设计。可以在一个研究任务里切换这些能力，不要求新阶段或重复写总结。

## 按信息价值选择行动

| 当前判断 | 可选行动 | 科学上需要说清楚的理由 |
| --- | --- | --- |
| 关键机制可信，但一个不确定性会改变采用决定 | 继续一项有判别力的测量 | 正反结果分别改变什么判断，成本为何值得 |
| 干预有潜力，目标、位点、粒度或校准背景错位 | 修订候选或拟合策略 | 哪项证据支持具体修改，哪些旧证据仍适用 |
| 原假设被可信观察反驳，或边际信息价值已低 | 暂停或停止该方向 | 反驳的是哪个主张，仍留下什么边界条件 |
| 方案定义完整，下一项真正未知的是任务结果 | 转入既有 L3 | 完整评测将解决什么问题；不要求局部指标先达到阈值 |
| 只发生工程/资源问题，尚无相关数值观察 | 沿对应恢复链继续，或保留未验证状态 | 请求、实现、资源与宿主错误分别交回适当负责方 |
| 有限预算内无法完成有价值的新试验 | 保留 B，提交当前候选与未完成问题 | 保留有效成果与继续研究入口，不把中断写成负结果 |

H1/H2 都是在明确完整方案上的改良，分别侧重方法启发和瓶颈驱动；B 独立保留，不占探索槽位。对 H3 判断的是当前创新机制值得获得何种证据，不因实现更慢或成熟证据更少而自动排除；不为创新标签额外安排实验或新增槽位；本轮 H1/H2/H3 三个最终候选仍全部进入既定 L3。低分或未入 Top-3 不自动结束灵感，由 Generation 按进展和具体下一步决定继续或暂停。必要时 select 可通过已有实验请求补上一项会改变选择的测量。

若完整候选与父包在同一开发清单上均有成对 FP/Q，仍应核对父包身份、校准样本及数量。条件不齐时可报告各自实测，若组件归因会改变下一步，再在同校准父状态上切换该组件。跨任务或跨视图方向不一致时保留各自结果。

若需要候选排序，采用当前 Brief 的实际目标与预算。完整双任务成绩只由有效正式结果比较并更新 B/方案库；局部证据可以决定下一笔投入，不能直接晋升正式性能排名。

## 形成足够短而可接续的结论

在现有科研正文或 `research_note` 中自然说明：当前最强结论、适用条件、关键反证或缺口，以及下一动作和预期改变的决定。引用必要原件即可，不新增固定输出表或阅读证明。

向现有 Recorder 交付可追溯的判断与条件；同一次执行不重复记成多次验证，工程问题不写成算法规律。没有新的可靠认识时允许不新增知识。本 Skill 不自动生成、修改或发布其他 Skill。

持续发展已有灵感时，也可把投入转向修复、参数必要性、收益解释或简化；以当前问题和证据说明增量，不要求再发明机制。暂停或恢复行动沿用原 action ID，确有新动作才另行记录；接口细节以资源生命周期说明为准。本 Skill 不增加调用或实验要求。

任务绑定独立开发视图时，完整 training-free 候选可在冻结后取得两个任务的配对 FP/Q。记录模型身份、校准条件、开发清单身份、视图完成范围及任务头的历史接触。Generation 可据此继续、修订、组合或暂存。记录已观察的官方结果时单列阶段和视图，保持原始比较依据。

## 从证据决定投入与主张范围

**触发。** 已有局部或完整结果，需要判断机制、任务收益、跨任务冲突、后续投入或正式验证范围。单纯归档和例行执行不需要重新评判全史。

**前提与范围。** 恢复确切候选/对照版本、实际协议、任务目标、评价视图与成本；只补会改变判断的缺口。

**步骤。**

1. 分开回答：测量是否有效、机制得到何种支持、任务有何价值、能否迁移。工具失败、计划和文献成绩不作为本地反证或成功。
2. 依比较意图检查条件：原法复现保留原设置；机制对比尽量保持量化条件；资源研究按真实存储/计算/延迟；迁移研究保留源域、目标域与任务头信息。不同意图不压成同一个裸分数。
3. 同时解释 FP、Q、Q−FP、单位和实际样本。双任务方向相反时按当前 Brief 的目标裁决，保留另一任务信息；不事后只报告有利指标。
4. 比较 B 时使用相应 before_l3 快照，避免候选已晋升后误判“没有新方案”。独立 B、开发阶段和官方阶段分别保留来源。
5. 选择继续、修订、暂停或转正式验证，并说明下一动作将解决哪项未知。三条已提交最终候选仍保有既定 L3 机会，局部代理不淘汰其中两条。

**结果解释与下一步。** 局部/任务一致且方案完整，进入相应验证；局部改善而任务下降，优先检查目标与传播；有效负结果可停止具体机制；只发生工程问题保持未验证；预算不足保存当前成果和具体续做入口。

**案例草案。** 一个 mixed 候选取得较高 mIoU，另一个是固定 W4A4。先看问题是否允许 mixed 及资源条件，分别记录结果；不能直接把前者晋升为 static W4A4 B。若目标是给定存储预算下最高 ADE，重新形成该资源口径内的比较，而非改写旧标签。

**复用边界。** 完整量化构造、开发视图完成、官方数据完成、部署加速是不同证据层级；低成本集成通过不能支持真实精度收益。只读已有官方成绩后做出的选择，应保留开发接触历史。
