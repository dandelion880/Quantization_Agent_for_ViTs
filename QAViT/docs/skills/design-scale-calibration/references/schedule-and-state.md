# 校准顺序、模型状态和计算预算

## 顺序是方法的一部分

一项校准决策的得分依赖当前输入和未改动后缀。先把前层装成 A4，再校准后层，与全部在浮点输入上校准，产生不同问题。应说明是前向、逆向、按功能组，还是证据支持的其他顺序；不将任何一种顺序视为普适原则。

对于 current 背景，已安装的早期候选会改变后续激活；对于 float 参考，有些旧缓存可以复用，但必须确认张量对应的模型版本和真实预处理。更改 weight/scale/zero、重参数化、输入归一化或 token 布局时，缓存有效性分别判断。不能因为文件名相同就复用。

多 pass 可以减少过时条件上的局部最优，也可能过拟合同一批校准样本，或只在等价状态间震荡。判断继续价值时可观察合法硬参数是否实质变化、配对目标是否稳定、下游响应和额外成本。无需设所有运行必须两轮或某个损失下降阈值。

## block 的三种不同意义

| 用法 | 真正完成的操作 |
| --- | --- |
| 按 block 调度 | 依次处理某个 block 内的多个位点；内部仍可能各用局部目标 |
| 观察 block 输出 | 某个候选的损失在 block 边界计算；候选可以只改一处 |
| block 联合重建 | 同时选择/更新一个 block 中多个参数，并处理它们的相互影响 |

当前 QAViT 已有第一种调度，frozen scale search 提供部分第二种能力；第三种需要核对具体候选和执行支持，不能由 `block` 字符串推断。提案缺少支持时通过既有 Coding 补齐必要实现，不因此新增研究角色或宿主阶段。

## 候选试评与正式安装

候选试评可以在拷贝、可恢复状态或受控临时替换下进行，具体沿用已有实现。必须知道试评改变了哪些真实 code/scale/zero、observer 和缓存，选择完成后安装的是否正是被评估状态。日志中的“best_alpha”不能替代真实参数安装。

量化权重 W、用于生成 W 的浮点基准、weight scale、rounding/code 彼此相关。若某个求解器会补偿舍入误差，单独重编码一个 scale 未必保留其结果。当前 frozen search 的 RTN/uniform 路径不能被默认为 GPTQ/GPTAQ 的重拟合入口；需要相应 solver 或明确的定制实现。

保持已有 FP/W4A32/Q0/B 等参照的身份清楚，候选被选中之后才能按既有规则更新研究状态。调试用 FP bypass、learned oracle、临时 observer 与正式 artifact 分开，避免状态串用。

## 成本与停止应服务当前问题

可以使用少量代表性图像/位点定位搜索形态，再根据证据扩大；不能只报告最好位点而隐去完整声明所涉及的其他位点。也可以直接校准完整模型，只要它比局部探针更快回答当前研究问题。

比较新旧搜索时，至少说清候选评分次数、数据量与实际时间的差异。必要时加入相近预算对照，以判断收益是否只是多花计算。cache 命中、batch、序列长度、滑窗与后缀重复通常改变实际成本；不要只给理论候选数。

候选排序失去区分度、合法硬状态不再变化、后续试验不会改变采用决定，或成本已超过当前研究价值时，都可以停止。停止理由可以自然叙述，不要求统一分数、硬阈值或固定次数。

该 Skill 输出的是可执行的校准设计与有依据的取舍；它既不替代 `evaluate-ptq-candidate` 对证据的判断，也不自动把成功设计固化成新 Skill。
