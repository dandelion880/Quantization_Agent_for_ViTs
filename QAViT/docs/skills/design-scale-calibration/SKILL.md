# 设计尺度候选、分组与校准安排

从当前部署允许的自由度和已知失效证据出发，构造可负担、能触及有用状态的校准过程。保留现有完整方案中已验证的部分；可以只改变一个候选生成器，也可以提出必要的联合更新。无需遵循固定的逐层或粗到细路线。

## 分清四个容易混用的对象

| 对象 | 含义 | 不应推出的结论 |
| --- | --- | --- |
| 推理量化粒度 | 哪些元素共享一个最终 scale/zero/codebook | 多个 scale 一起搜索不等于改变粒度 |
| 校准共享组 | 哪些现有参数共用倍率或候选决策 | 共用倍率不等于共用绝对 scale |
| 重建/评分范围 | 哪些输出决定一个候选的优劣 | block 输出目标不等于整块所有参数联合拟合 |
| 执行调度 | 哪些位点以何种顺序、背景和次数更新 | block 调度不自动实现 block reconstruction |

恢复参数初值、合法域、实际码本和冻结范围。已有独立 uniform grid 可按扁平 indices 选择成员，设置相对倍率及 codec 允许的整数 zero；重新分组需要相应执行实现。令 `s_i = α_g s_i,0` 时，明确 `s_i,0` 是固定初始参考还是本轮局部参考；避免多轮把倍率错误累乘。零初始 scale 不能通过纯乘法搜索变为正，需要符合码器语义的独立候选。详见 [候选与分组设计](references/candidates-and-groups.md)。

## 把现有证据变成候选，而非常数

- **参考解显示类型/层/组间差异**：提出按 token 类型、运算角色、深度或前向响应分组的候选；这些只是可检验的结构，不能复制参考解的逐实例参数或成员划分充当独立 PTQ。
- **候选范围覆盖参考，但性能仍差**：检查共享自由度和选择指标。盲目拓宽范围或加密网格不一定有效。
- **同一组内的最佳响应明显不同**：考虑拆组；若样本不足导致不稳定，则考虑更稳健的合组、较小自由度或留出确认。部署粒度是否变化需单独判断。
- **相邻编码/scale 与 zero 存在功能交互**：可比较少量联合候选、坐标更新与简单单参更新；不默认组合越多越好。
- **搜索代价大、有效候选少**：从分位数、饱和边界、码格事件或局部近似生成候选；剪枝规则需保留当前有价值的解，速度收益由实际成本证明。
- **更改前缀后旧选择失效**：更新必要缓存，考虑有限 revisit；不要将增加 pass 作为无收益后的默认补救。

候选生成可以由解析式、前向统计、已有规则或明确允许的只读敏感性分析支撑。改变编码形式、重参数化或权重补偿属于 `adapt-quantization-method` 的机制设计；候选在给定形式内如何搜索由本 Skill 负责。

## 将搜索过程绑定真实模型状态

保留原方案作为可恢复起点。说明采用 float、current 还是混合参考输入，各次安装后哪些激活需要刷新；试评候选不能污染未选中的模型、observer 或后续缓存。目标范围和 lookahead 的定义来自 `select-calibration-objective`，本 Skill 决定如何在预算内调用它、哪些参数同时变动、何时重新评分。

当前 QAViT 的 operator/block 调度、多 pass 和 frozen scale search 已有实现，但并非任意组合都可运行。尤其 W 的 frozen reencode 仅覆盖当前支持的 RTN/uniform；不能把 GPTQ/GPTAQ 的 scale 换掉后仍称相同求解结果。已有参数、重编码参数和重新拟合的权重需要分清。更多见 [顺序、状态与成本](references/schedule-and-state.md) 及 [源码兼容说明](../../SCIENTIFIC_SKILLS_COMPATIBILITY.md)。

## 判断是否该继续增加搜索

候选覆盖、排序正确性、顺序交互各自可能限制效果。用最能改变决定的证据区分它们：候选足够而目标排序失真时先改目标；目标稳定而自由度不足时改候选；条件排序有效而完整方案失败时检查实际前缀、联合状态和任务迁移。必要时使用判别性实验，不要求三项都补齐。

新方案应足以在现有 Coding→Safeguard→数值执行链中被实现：说明改变的参数、候选来源、分组规则、评分调用、安装与停止方式，保留其他已验证配置。研究说明可以自然叙述，不新增机器强制字段或搜索轮数门槛。

可按问题读取真实案例：[PTQ4DINO 的两阶段前向分组](../../../knowledge/research-skills/research-routes/ptq4dino.md)、[AdaLog 的搜索空间与预算](../../../knowledge/research-skills/research-routes/adalog.md)、[GPTAQ 的输入背景与顺序](../../../knowledge/research-skills/research-routes/gptaq.md)、[ERQ 的联合误差](../../../knowledge/research-skills/research-routes/erq.md)。案例提供推理方式，不提供跨模型默认最优超参数。

## 分开候选空间、搜索器与重构调度

**触发。** 已知要拟合什么，需要设计 scale/zero/codebook 候选、共享组、粗细搜索、有限联合更新或重构次序；加密搜索没有带来预期收益。

**前提与范围。** 已有评价目标或可先采用明确的临时目标；知道当前协议允许的推理表示与离线更新对象。优化器步数、候选评估和数据呈现都属于成本。

**步骤。**

1. 分开四个对象：最终推理粒度、校准共享组、评分/重构范围、更新调度。block 调度不自动意味着联合 block reconstruction。
2. 恢复初值、合法域和真实码本；倍率相对哪个 base 明确固定，zero 按实际编码定义。零初始值不能靠纯乘法开启新范围。
3. 判断瓶颈是候选池没有好解，还是生成/选择过程找不到。对已有好解可先做受限投影诊断；投影使用参考答案时不当作独立选参成功。
4. 固定表示与目标比较搜索器，或固定候选池比较目标。FPCS、显式网格、进化搜索比较实际候选数及准备成本，不能让“同一倍率网格”掩盖不同码器。
5. 若使用有限重构，明确阶段更新对象、输入上下文、优化停止点及重校准时机。保留硬量化状态，观察拟合与独立确认是否分离，再决定扩大单元、数据或预算。

**结果解释与下一步。** 好解不在池中，改自由度/候选生成；好解在池中但选不中，转目标选择；增加步数只改善校准误差，考虑数据覆盖、扰动或缩减自由度；前缀改变后旧选择失效，研究重估和顺序。

**案例草案。** AdaLog 原表示在同一实际候选池上并未优于现有配置，而完整 FPCS 更快找到好状态。应把结果归到搜索效率，而非将全部收益归给对数底数；若增加搜索预算后差异消失，可研究更廉价的候选生成。

**复用边界。** 不固化统一 optimizer、步数、组数或搜索网格；I&S 等阶段性配方不能改成所有参数同时 Adam 后仍称原法。有限校准 PTQ 可以保留优化结果；只有额外声称独立无优化规则时才需要独立重建。
