# 判别性实验设计模式库

**仅按争议选择一个或少数模式。** 下表不是实验门禁或固定 L0→L1 流水线。

| 科研争议 | 最小有效对照 | 结果怎样改变判断 | 常见陷阱 |
| --- | --- | --- | --- |
| 新网格本身有效，还是校准输入造成改善？ | 固定模型/位点/样本与量化 peer，必要时做“网格 A/B × FP/真实量化前缀拟合输入”2×2 | 看网格主效应、输入主效应及交互是否改变机制排序 | 同时改 codebook、校准集、搜索预算，会使对照不可解释 |
| 新 rounding/补偿目标有效，还是多给了参数自由度？ | 固定方案起点和校准预算，与最简单的 scale-only/RTN 等改动比较 | 复杂机制是否贡献独立收益 | 与不可比起点比较或只在训练/搜索集报告 |
| 某一激活边确实主导误差吗？ | 冻结其他量化器，针对该量化边作一次有方向的局部旁路或干预 | 看局部和后续输出是否如预期改善 | 把旁路后的 A32/W32 状态称为完整 W4A4 |
| 前缀失配还是目标参考失配？ | 以相同冻结前缀比较拟合输入选择、FP/peer 目标，必要时做双参考报告 | 区分输入噪声补偿与局部自重构 | 用不同前缀或不同校准图让变量混淆 |
| W/A 之间有交互吗？ | 匹配 W-only、A-only、joint，必要时比较 W→A / A→W 或局部联合校准 | 分析单因素能否解释 joint，顺序是否稳定 | 准确率不能简单做线性误差相加来当因果结论 |
| 局部收益能迁移吗？ | 原冻结候选 + 相同 holdout + 后续 logits/子任务观测 | 若局部有益而下游无益，调整研究优先级 | 只选择改善最大的层报告、重复用 search 集 |

## 实施时先写“预测差异”

一份有价值的请求至少能够自然语言回答：

- 正在区分的两个解释分别是什么？
- 哪个可控制变量与哪个观测最能把它们分开？
- 如果出现结果甲或乙，下一步决策会怎样不同？

上述是设计思路，不是新增 JSON schema、字段检查或 Safeguard 审批。Coding 可以自主选择工程实现。

## 低成本选择

- 若逻辑或极小单元可以证伪机制，先用 L0；必要时再做真实 L1。
- 若历史试验已有同条件冻结信息，可复用，减少新 Coding 与模型加载。
- 只需要下游传播证据时，不必为其他候选重新校准整网。
- 若真实任务指标是唯一剩余疑点，且有可信完整候选，直接考虑独立完整评测；不强制补充一长串局部 profile。

## 结果解释

对负结果也保留明确条件；将模型/校准/样本配置不一致、数值失败、预算延期与机制不成立分开。必要时停止继续探索，而不是把更多实验当作天然进步。
