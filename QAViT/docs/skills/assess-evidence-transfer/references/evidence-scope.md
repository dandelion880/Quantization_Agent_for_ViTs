# 实验结果的证据层级与迁移范围

此处的“层级”描述**某项观察能支持的结论种类**，不是必须逐级通过的审批序列。证据级别高也可能有偏差；低成本证据若已反证核心机制，足以决定暂停。

| 证据来源 | 可以支持 | 不能由此推出 | 应保持的比较上下文 |
| --- | --- | --- | --- |
| 公式、单元测试、少量合成张量（L0） | 数学可行性、代码数值一致性、某种机制是否存在反例 | 真实模型收益，尤其跨层或整网准确率 | 输入分布/边界、浮点误差、码点和运行精度 |
| `profile_distribution` 类真实激活统计 | 异常值、长尾、分通道差异、饱和风险等事实 | 统计异常就是 task drop 的因果主因 | 位点、token 集、校准/验证划分、样本量 |
| RTN 或小规模局部 QDQ/sensitivity | 局部量化易损位点及某个简单量化器的性能线索 | 复杂校准后的最终排名 | 权重/激活/联合、quantizer、同一前缀与参考 |
| 冻结前缀下的局部校准或 ablation（L1） | 在该冻结上下文和相应参考下，某干预方向是否有效 | 自由重校准全网或独立验证必然有效 | 前缀冻结状态、同 peer/FP 参考、calibration/search 与 holdout |
| 下游 logits、patch/token 特征、整网任务代理 | 局部变化是否传到较接近目标的表示或预测 | 完整评测 mIoU/Top-1 或实际硬件吞吐 | 比较模型与数据相同、目标日志相同、误差度量一致 |
| 独立完整模型评测（L3） | 特定完整方案在约定模型/数据/评测合同下的质量结论 | 跨模型泛化、训练时长/部署硬件收益、新数据必然复现 | static W4A4 合规身份、冻结评测协议、真实任务、样本与划分 |
| 真实低比特部署测量 | 在该 kernel、框架、批量、硬件下的延迟/吞吐/显存 | 其他芯片、算子实现或 batch 同样加速 | 使用了真正 INT4/W4A4 kernel 吗？与 FP/其他量化基线是否公平？ |

## 五个常见混淆

1. **相对 peer vs 相对 FP**：改进了当前量化候选相应层输出的 SSE，不意味着同程度恢复了 FP 输出；必须看真正指标的参考。
2. **calibration/search vs holdout**：用了同一组图多次搜索后取得的最优值，反映优化适配；独立 holdout 更适合估计泛化。
3. **局部旁路 vs 完整低比特**：一次恢复 FP 的层可识别可疑路径，不能与完整 W4A4 候选按同一部署身份比较。
4. **误差均值 vs 关键样本**：当 token energy、类别、极少数异常图占主导时，均值改善未必有任务收益；也不要对少数极端样本做事后选择性报告。
5. **同协议结果 vs 迁移主张**：在 DeiT-B 分类成立不等于在 DINOv3 冻结分割头或 Swin 上成立；跨任务差异是新的科学问题。

## 一个数值例子

某局部方案相对原冻结 peer 的 SSE 降低约 5%，相对 FP 目标只降低约 1%；这是两项不同参考下的真实局部变化（前提是测量定义与冻结条件一致）。可以说“方案改善了该前缀条件下的局部误差”，但不能说“整网性能恢复 5%”或“Top-1 将提高 5 个点”。下一步若其机制声称阻断误差传播，则优先看 **同一前缀与样本上的下游观测**。

## 证据不一致时

不要总是把它解释成实验“失败”。先辨认：比较对象错位、校准搜索过拟合、随机波动、实现误差、评价参考不同、量化前缀变化，还是**原机制假设确实不成立**。若关键证据缺失，只说当前尚不能推断。给出可以最大程度澄清的一个追加观察即可。
