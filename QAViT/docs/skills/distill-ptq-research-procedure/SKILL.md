## 沉淀会改变下一次决策的流程

**触发。** Recorder 发现可重复使用的诊断、选择、修复或停止办法；或人工新研究材料补足现有流程。只出现一次成绩、最佳倍率或未执行想法时，通常保留知识/研究笔记即可。

**前提与范围。** 有真实来源和明确的可迁移决策。人工素材、原论文方法学和本批经历都可以提供流程，但需保留不同证据身份；本地经验只用当前可见、可引用的真实记录。

**步骤。**

1. 把经历从“做了某方法”改写为“遇到什么现象，什么证据让下一步改变”。识别触发、前提、关键观察、结果分支和反例。
2. 查当前 Skill 目录的真实正文与版本。已有同义流程时修订触发/分支/边界，而非增加一个论文同名 Skill；没有独立决策价值则不发布。
3. 提炼结构性规则，移除某次层号、倍率、随机 seed 和成功分数等实例答案。保留确有作用的条件，如实际 Q 后缀、数据用途或完整父状态。
4. Recorder 使用现有 skill_updates 合同，绑定本批真实卡片的窄 payload 字段；人工文献种子走资料入口，不能伪造本批来源。修订/停用使用当前可见 base 版本，来源冲突保留原件。
5. 写成条件化的步骤与结果解释。没有支持通用成功的证据时，发布为有来源的研究流程/待验证启发，而非“已验证有效方法”；需新实验的部分交下一轮指导。

**结果解释与下一步。** 新经验只补一个反例，修订现有边界；流程在不同条件反复有效，扩大范围时带上相应真实来源；原判断被反驳，修订或停用但保留历史；工程失败揭示来源恢复错误，可以沉淀恢复流程，不能上升为算法失败规律。

**案例草案。** 一批证据显示局部 NMSE 的赢家在独立确认中更差。可将“同池比较选择 regret，并区分参考输入”补入目标选择 Skill；不能发布“永远不用 NMSE”。如果缺少独立确认，先把观察和下一项检验写入知识与研究指导，不补造结论。

**复用边界。** Skill 不是完整模型包、论文摘要或参数数据库；不得把方法数量、调用次数当科研成功。新种子不能覆盖已有运行发布谱系；有来源的人工流程与 Recorder 流程同等可检索，可信度由实际证据决定。

**来源。** 已读 `core/skills.py` 的 `initialize / prepare / publish / reconcile`、`agents/prompts/recorder.md` 与 `tasks/record.md`；现有 `knowledge/research-skills/` 人工案例；`04_RESEARCH_WORKFLOWS.md` §12。这是现有发布通路上的内容流程，不增加发布工具或新的审批角色。
