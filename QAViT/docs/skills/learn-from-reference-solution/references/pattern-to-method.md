# 将参考模式转成独立 PTQ 方法

## 用一个可以失败的解释连接观察与方案

有价值的结构通常包含：观察到什么差异、它可能改变什么数值/功能、有哪些其他解释、可以不依赖 oracle 的规则是什么，以及何种结果会使该规则失去价值。例如：

> 某些 patch 组的参考倍率明显小于同层特殊 token。可能是主体分辨率比尾部保真更影响当前 dense 表征，也可能只是不同初始 scale 的偏差。若按当前前向响应分组后仍能取得相似功能改善，这个结构才有望转成无需训练的候选规则。

这是一种研究提案，不是从参数中直接读出的结论。可先检查实际 rounding/clipping 与投影后误差，再决定是否需要任务消融；不要一开始扩展到全模型排行榜。

## 三个不同问题不要合并

1. **表示能否做到？** 同一合法格式的参考改善支持存在可行状态。它仍可能是局部最优，也可能依赖新开放自由度。
2. **候选族能否包含？** 对参考做共享、聚类或网格投影，查看功能保留程度。最近参数投影的成功是有用线索，失败不是全族不可能的证明。
3. **选择器能否找到？** 在不读取参考标签的条件下，用最终允许信息选择候选，评价其功能与成本。编码误差比投影更低不保证任务更好。

这三个问题可以按需要选择，不要求每条路线都依序完成。若已有可靠完整方案，直接研究其新机制或迁移也合理。

## 可独立执行的替代规则

| 参考中的观察 | 可提出的独立规则 | 需要防止的偷渡 |
| --- | --- | --- |
| 某些 token 类型的倍率偏好不同 | 从模型布局识别类型，分别试有限候选并评价 | 把每个类型的参考最佳倍率硬写为当前实例答案 |
| 同层若干 scale 响应相近 | 按前向粗候选响应构成组，组内细搜 | 直接使用训练后聚类成员，声称分组是免费先验 |
| Q/K 或相邻编码有联合效应 | 少量联合提案与真实相邻重编码评分 | 默认为所有层都强耦合，或复制参考联合参数 |
| 原网格漏掉有用编码状态 | 由前向数据/码格事件生成新候选 | 用参考距离决定保留哪些候选而不披露 |
| 局部目标选错后缀重要方向 | 以真实量化后缀或相关特征设计评分 | 根据最终验证结果无限调组合权重 |

结构级算法设计可以受历史参考启发，这是正常研究过程。需防止的是每个新实例在运行时仍读取答案，或者对同一测试集反复调规则后称未见泛化。

## 重新构造是关键验证

实现独立方案时，从没有安装 oracle 参数的 Q0/基础模型重建。对当前实例的倍率、zero、组成员、候选池筛选和阈值，说明其来源为结构、许可数据或已冻结的通用设计。一般设计超参数可以在开发数据上选择，之后在后续确认任务中保持定义；不要把模型特定答案换名为“超参数”。

若 independent 方案不及 oracle，区分缺失自由度、排序失配、顺序变化或参考过拟合，选择一个当前值得解决的问题。无需保证完全追平参考，成本更低且结果有价值的折中也可以形成方法。

## 形成可信的研究叙事

可用“真实失败 → 受限参考 → 结构观察 → 可区分假设 → 独立规则 → 失败/成功边界”的因果脉络组织论文，但只写真实已发生和已验证的部分。先验直觉、事后解释与预先预测分别表述，负结果可以说明为何放弃某种复杂度。研究路径不要求每步成功，更不应该为了叙事而修改原实验记录。

对 QAViT 的贡献是能借助参考发现并验证新 PTQ 规则；证明这种能力需要后续真实任务上的行为与科研成果比较。此内容包本身不证明 agent 已达到该能力，也不包含自主 Skill 沉淀。
