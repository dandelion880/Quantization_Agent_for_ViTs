# 两批科研链简化实施记录

本轮基于开始时已有未提交修改继续实施，未恢复旧文件、未覆盖历史运行。工作范围为单实现实验链和确定性职责归位；未重构检索、短标签、L0–L3、Recorder触发机制，未启动完整科研贯通实验。

## 实质改变

1. 新实验先持久保存原始需求，Coding交付一份实现与必要执行选择，程序再冻结实际执行记录。生产Reference任务、独立源码、双实现比较worker及相关批准依赖已删除；已有服务继续直达执行器。
2. Safeguard直接接收原始需求、当前源码、执行条件，提交批准决定与科学理由。批准由程序绑定请求/执行/源码哈希及宿主版本；修改后失效，缓存不能绕过该检查。保留原浮点基准、真实误差、数据使用和L3导出重载检查。
3. 执行失败按现有任务局部处理：实现问题携当前源码和具体反馈返回Coding，当前实现可修订；相同失败源码及条件不重跑；宿主/资源问题归工程失败，科学歧义才回原研究者。沿用两次修订额度。
4. 模型可见视图隐藏固定身份和执行镜像。程序补充轮次、来源、版本、资源、已明确的数据条件、随机种子默认值、参数镜像。可选预测/验证夹具无需填写。集合/范围约束仍检查实际选择，未知科学选择不伪造。
5. Recorder逐条从真实证据绑定完整或部分scope；模型哈希无需模型填写。不同实测条件不自动拼成共同范围。无效条目保存原稿、索引和问题，暂不进入知识层；其他有效更新与科学分析正常保存。事实归档、复盘、知识待核实分别记录。
6. 能力/位点目录读取不要求校准、不生成校准事实；实际profile测量把参数绑定到真实数据视图。固定协议可直接补齐，显式冲突有局部错误。格式修复统一支持同任务repair_patch，不要求重做整份科学分析。

## 验证记录

两次最短真实链均完整通过；最终生产实现的记录为 `real_chain_final/service_validation.json`。Generation提交的原稿仅含问题、测量、科学对照与服务/位点选择，无哈希、资源、预测或fixture；随后完成唯一Coding、真实Safeguard批准、真实数值worker及原Generation续调，并生成引用该Evidence的HypothesisCard。没有Reference或verification任务。

最终实测：DeiT-B、blocks.0.attn.proj、32张既有calibration图像、4,841,472个激活元素；输入relative MSE=0.10455330269849535，局部输出relative MSE=0.03763044878483915。数据来源为`real`。Evidence为`EvidenceCard-4ffe25f198c04d3eb3567d89cc0e3ff8@1`，原研究者产出为`HypothesisCard-9b52bd09470a4dd7a9a0c42b24bb2fc6@1`。第二次运行用于验证补齐后的实现身份/参数范围绑定，不作为独立科研重复证据。

针对性回归已覆盖：实际CPU worker抛出实现异常→同请求修订→新批准→实际成功计算→原研究者；旧批准随源码/条件改变失效；未改源码拒绝重跑；科学约束冲突；Recorder缺省/部分scope、跨条件与跨源码不合并、混合有效/无效更新、重启幂等；能力与权重查询无需校准；两轮自主循环、H*/H4、辩论、最终选择及CPU小模型实际导出/重载和L3结果协议回归。

最终全量回归 **336/336通过**（272.550秒，`regression_clean.log`）；结构审计通过（134个Python文件、196个快照文件，`structure_delivery.json`），CLI帮助入口和`git diff --check`通过。初轮失败日志保留：包括旧双实现/过早冻结断言、遗留验证入口，以及新增测试在主进程安装Landlock导致的后续权限错误；后者已改为真正独立worker执行。单独格式修复9项通过，完整回归随后重跑。

真实验证入口为 `QAViT/tests/validate_code_service.py`。本次选用已有 `two_rounds_20261104_r2/input.json` 的DeiT-B权重、ImageNet清单、GPU 0、32张校准图像、既有角色模型。仅申请一次0.995分位数静态4-bit局部QDQ；不读取final、不做整网精度、不启动辩论或完整轮次。

## 明确边界

- 本轮不证明新算法科研优势，也不声称完整ImageNet/ADE精度或硬件加速。
- CPU夹具回归用于检查程序行为；真实订阅模型及真实数据测量另列证据。
- 宿主/实现错误归属基于真实调用栈与明确异常条件；宿主bug若由插件调用触发，仍可能需要工程诊断，不能声称程序已自动判断所有异常根因。
- 历史Reference产物仍可读取，新流程不依赖旧审批，也不把旧记录迁移成新批准。
- 真实验证后仅修正README中的服务版本文字和一个测试的子进程隔离；生产源码未再改变。`DELIVERY.json`记录实测与交付完整源码哈希及两文件差异，历史批准不被挪作新源码批准。
