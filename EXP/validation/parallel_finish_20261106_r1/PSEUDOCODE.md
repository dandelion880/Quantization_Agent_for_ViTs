# 当前 QAViT 伪代码（2026-11-06）

```text
输入：ResearchBrief、原有科学约束/模型/协议、预算、授权 GPU 集合
新运行模板：active_segments + exclude_numeric_wait；GPU 0..4；LLM 4；实验并发 5
恢复：核对配置和源码身份；先停止旧进程/接收持久回执；沿用已消费预算、任务和请求身份

每个受外层监控的运行段：
    从累计余额开始，不重置消费；旧模式保持历史语义
    循环：
        检查预算和磁盘；轮询、校验并接收各任务完整回执
        将真实 Evidence 返回绑定的原请求；失败/中断保留真实原因
        只在纯数值执行、资源排队或等结果且没有智能体工作时开启等待扣除区间
        推理/Coding/Safeguard/Judger 或同步宿主工作开始前关闭扣除区间
        并行实验/推理的重叠只按一个时间区间结算
        如智能体余额已不足：先接收已启动数值实验，再按原收尾流程结束

        Generation(H1/H2/H3)：各自可反复申请实验、接收反馈、修订，然后正式提交
        Screening：沿用原科学判断，不新增科研或实现门槛
        独立推进 H1-H2、H1-H3、H2-H3：
            每场 A/B 独立提交 -> 仲裁 -> 必要实验/下一回合 -> 正式结案
            当前任务获得自身结果与明确引用支持；公开 Memory 按需读取
        三场全部结案后：复用既有裁决或 Judger 选 H*，持久化且不重选
        Evolution：只加强固定 H*，可自主实验，提交 H4
        Screening(H4) -> 唯一 H4-H* 挑战 -> 父子最终选择
        原最终计划 -> L3（如本次启用）-> Recorder -> 下一轮

        调度：
            Judger 至多 3；同一场互斥；非 Judger 共用 1 个 LLM 通道
            数值实验独立计数；原非数值 worker 容量保留；不共享模型锁或全局 numeric 锁
            请求实现与审核完成即可竞争空闲 GPU；Coding/审核继续处理其它请求
            忙卡留在 ready；核对持久队列占用和 OS 租约；不增加尝试数、预算预留或科研失败
            跨运行 GPU 文件租约 -> UUID/设备节点映射 -> 持久 worker
            租约由 worker/分片继承；进程退出、超时、中断后释放

单份代码实验：
    冻结原始请求 -> Coding 一份实现和执行选择 -> 绑定执行卡 -> Safeguard
    -> 原执行器 -> 检查数据/模型/来源和真实结果 -> Evidence -> 原请求继续
    缺参修订一次返回当前已有合同的全部缺项，不猜参数，不新增角色/验证关卡

原生分类实验内多卡（尽力启用）：
    非训练 quantize_evaluate：原单卡 prepare/校准/导出/重载一次
    evaluate_artifact：直接加载已冻结包
    分片按原 sample_ids 的 stride 划分，每张图仍使用原逐图前向
    子进程从相同冻结包加载；核对 FP/candidate digest 和包哈希
    原 evaluate -> 原 aggregate：整数正确计数、FP64误差累加器、max_abs_error取最大
    核对没有重复或遗漏样本，恢复原样本顺序；原分片结果归档
    不支持或空闲卡不足：沿单卡路径；不更改算法/校准/训练语义

中断/暂停：
    停止 Supervisor/worker/独立分片进程；保存完整或中断回执
    确认所有自有进程退出才结束预算段；暂停间隔不扣时
    未确认崩溃区间从最后等待检查点之后保守计入
    恢复保留消费和旧尝试，重试仍沿原有界策略；不会把部分结果发布为 Evidence
```

本伪代码描述当前实现。单元/脚本控制流、真实小样本和完整真实 L3 的验证范围分别见 [REPORT.md](REPORT.md)。
