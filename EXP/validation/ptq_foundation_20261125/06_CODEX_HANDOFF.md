# 给 Codex 的接入说明

本包交付的是已经起草的方法文字与科研语义。第一版完成协议确认和方法拆解；本次补全增加五个工作包的接入正文与验证说明，范围见 07_FIVE_WORK_PACKAGES.md。Codex 任务提示词按用户要求仅在会话的可编辑写作块中提供，不收入本包。本会话没有修改运行中的 QAViT，也没有启动完整科研运行；这些材料用于用户随后交给 Codex 的实现任务。

## 1. 接收这些文字时保留什么

保留方法的三个层次：完整原配方、可组合机制、研究工作流。文件可以按实际架构拆分、移动和建立索引，但不能把长文重新压缩成几句宣传性摘要来代替原规格。正文中的数学对象、张量轴、顺序、参数、例外、来源差异和未核实项都有具体用途。

代码中的原有支持与本包的新材料合并维护。`existing_methods_delta.md`、AdaLog/FQ 等已有组件补全不应变成重复插件；共享求解器、metric、数据与状态设施供多套完整配方复用。QEP 等跨领域 PTQ 只能以实际论文任务为证据，不自行继承成已验证 ViT baseline。

用户的 QAT 排除要求适用于方法正文、配方、组件、metric、Skill 和主题生成；不要从排除账本重新生成任何 QAT 方法内容。混合论文只使用已经核实的独立 PTQ 分支。

## 2. 接入后应有的四类身份

| 对象 | 需要保留的身份 |
| --- | --- |
| 完整原法 | 论文版本、作者实现版本、原始配置与论文/代码差异 |
| 可组合组件 | 数学定义、输入输出、状态变化、前提、重估依赖 |
| QAViT 变体 | 相比原法的明确差异及其理由、适用配置与新证据 |
| 实验结果 | 实际模型包、覆盖/位宽、数据用途、构造预算、评价视图和观测 |

方法文稿可用不等于接口可调用；组件实现了不等于完整配方已复现。来源账本与运行能力目录保持不同职责，避免让一个 `implemented=true` 取代全部事实。

## 3. 从共同基础到完整配方

接入应覆盖全部已确认的 PTQ 材料，实施顺序按依赖关系安排，不按每次只加一两个名字推进。

首先更新协议和执行事实模型，使有限校准优化、固定与动态粒度、精度例外、任务/数据用途、附加成本和可重载状态有真实表达。当前旧协议中的 training-free 总限制不能继续通过父包规则、结果核对、提示词或排名逻辑间接生效。

随后补共享能力：校准与冻结评价分离、参数更新/重构设施、精确 reference 语义、metric 准备与评分注册、固定 token/通道组、搜索与调度、补偿与结构状态、合成数据、精度和格式分配。已有 frozen_trials、propagation、calibration、变换与数值量化器继续复用。具体影响文件见 `03_BASELINE_AND_INTEGRATION.md`。

在这些共同能力上组合各原配方。对论文/代码冲突保留两个配置；对尚未闭合的来源保留明确状态。本文中的建议接口名称不是当前工具 API，注册名称按真实宿主设计，不要添加假工具供模型调用。

最后连通方法短目录、按需长文检索、分类标签、主题生成与角色提示词，完成本轮必要的低成本真实集成验证。更广泛的综合调优与完整运行保持为下一阶段。Prompt 的分类原则见 `05_TAXONOMY_AND_TOPIC_DESIGN.md`，具体角色正文见 `09_ROLE_TEXT_BLOCKS.md`，跨方法研究过程与 Skill 内容分别见 `04_RESEARCH_WORKFLOWS.md`、`10_RESEARCH_SKILL_CONTENT.md`。旧运行仍按其原始协议解释。

## 4. 精确数值接入的检查重点

检查应针对具体数学风险，避免为每段文稿建立只复述实现的测试。

- **表示与编码：** code 个数、端点、零值、舍入、符号/索引/额外分支、元数据和反量化全部一致。
- **等价变换：** 使用真实图边、消费者和权重轴，比较未量化函数；变换后更新 W 网格与依赖统计。
- **目标与参考：** FP/量化前缀、parent/candidate 输入、task/head、梯度估计、损失方向和归约轴明确，缓存不跨错误版本复用。
- **重构与补偿：** 仅更新配方声明的状态；优化结束可独立重载；局部 loss 改善与任务收益分开。
- **覆盖与资源：** 首尾层、attention 边、head/neck 和旁路均进入实际配置；参考 QDQ 与真实 kernel 时间分开。
- **数据与结果：** 统计池、敏感度池、搜索/拟合池、选择集和最终评价集按实际用途记录；原作者结果不充作 QAViT 实测。

源码或原文确有歧义时，保存能够定位的差异和候选解释。不得为了让流程跑通而暗改定义；必要的适配建立独立变体，原法身份保留。

## 5. 全流程验证要回答的研究问题

后续完整运行除了检查能否结束，还应确认：Focus 能否从真实问题找到新增方法；Generation 是否读取原配方并产生机制不同的可检验候选；Critic 是否抓住具体的目标/比较失配；Coding 是否正确复用组件；L3 是否按实际配置评价；Recorder 是否把结果提炼成有适用条件的经验。

成功标准是 QAViT 能以更强的已验证 PTQ 起点提出和检验科研假设，并积累可靠结论。新增文件数、方法名数或 Skill 调用次数不能单独代表科研能力提高。
