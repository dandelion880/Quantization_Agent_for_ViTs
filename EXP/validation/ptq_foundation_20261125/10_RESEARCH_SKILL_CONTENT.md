本文给出 **11 个方法学 Skill**：修订现有 7 个身份，新增 4 个有独立职责的流程。它们是 QAViT 应用内的知识正文，供 Codex 按其现有 `docs/skills/` 与版本发布结构接入；本包集中提供文字，具体拆分沿用实际源码约定。原论文细节保留在方法材料，Skill 负责在什么情境下作什么判断、怎样取得证据、结果如何改变下一步。

## 接入与使用约定

已核对 `core/skills.py`：人工种子由 `docs/skills/` 初始化，Recorder 经现有批次产生版本化修订；运行角色通过简短目录和 `read_asset` 按需读取。下列“触发”可映射 `description`，“前提与范围”映射 `scope`，“步骤/解释/案例”映射 `procedure`，“复用边界”映射 `counterexamples`。不要把这里的案例文字直接包装为已发生的 Evidence。

**全体共同边界。** 仅限已核定 PTQ，QAT 及其训练配方不进入这些技能。有限校准优化按当前协议允许的更新对象和预算执行；只读梯度、有限重构与推理时动态行为分别说明。当前实验无需调用全部技能，也无需按本文顺序运行。已有证据足够时可以跳过新测量；没有可用技能时仍可自主研究。各技能的结果写回现有研究正文、research_note 或 Recorder，不新增必填表单或审批。

文献、人工历史和本地实验是三种来源：前两者可以启发同等具体的工作流程，本地有效 Evidence 才能更新本次实测结论。文中的“案例草案”均是**拟议情境与结果分支**，未在本次 QAViT 上运行；只有明确引用的既有人工案例保留其历史身份，不能当作本次自主发现。

## 1. diagnose-ptq-failure：从误差现象定位可干预机制

**触发。** 量化性能异常、W/A 联合作用不明、局部误差与下游冲突，或研究长期围绕同一位点而缺少传播依据。单纯加载/接口错误、已明确的例行校准不需要本技能。

**前提与范围。** 至少能明确症状对应的 FP/量化状态、任务与实际输入；不要求已有全网 profile。诊断允许局部旁路，但其结论不等同完整低比特方案收益。

**步骤。**

1. 先核对症状是否来自同一样本、任务头与模型版本。若改写后的 FP 已变化，先检查结构/等价变换或评价路径，暂停对量化器的归因。
2. 列出会导致不同下一步的解释，例如“本边码点分配失配”“上游输入偏差”“下游放大”“W/A 误差抵消被破坏”。不为形式要求凑固定数量。
3. 复用已有配对传播与少量代表性边界，分辨全 FP 轨迹参考、同一 Q 输入下的局部 FP 参考，以及真实候选输出。候选改变上游时，旧 parent 输入上的 local_fp 不再是候选的同输入局部对照。
4. 只对值得区分的解释安排冻结单边、W-only/A-only、块旁路或合法码器变更，观察近端及任务相关下游。W/A 分别误差不能直接相加；联合输出还含交互与交叉项。
5. 依据结果选择干预或保留未知。已能决定下一步时停止扩展 profiling。

**结果解释与下一步。** 局部失真大但下游不敏感，降低该热点优先级；当前块局部新增小、输入偏差大，转向上游或校准背景；A 好转却 W/A 联合恶化，研究误差转移/求解顺序；CLS 好转但空间 patch 恶化，保留任务冲突并检查实际 dense 读出。

**案例草案。** LN 后范围缩小而 ADE 开发表现下降。先查看变换前后 W 分布和真实输入上的线性输出，再用相同父状态的必要 W/A 对照分辨“激活改善被权重损失抵消”与“后缀失配”。仅当它们导向不同修订时追加测量，不强制完整四组合。

**复用边界。** raw q99.9、最大 MSE 或一张热图不是根因；旁路收益不是合法 W4A4 可达上界；工程失败不反驳机制。模型 token 与 readout 从实际适配器读取。

**来源。** 现有 `docs/skills/diagnose-ptq-failure/`；`04_RESEARCH_WORKFLOWS.md` §3–4；[ERQ 的误差耦合与补偿材料](methods_reconstruction_metrics.md#erq-icml2024)、[QEP 的输入/目标关系](methods_reconstruction_metrics.md#qep)、`metrics_registry.md` §6。诊断分支为 QAViT 研究设计，不是作者试错历史。

## 2. adapt-quantization-method：从机制到完整 PTQ 改良

**触发。** 已有瓶颈、成熟原法可迁移的机制，或值得形式化的理论构想，需要决定改变何种表示、变换、补偿或结构。H3 不必先取得实证瓶颈。

**前提与范围。** 能恢复完整父方案，或明确新构想的完整化路径；原法训练边界已确认。来源不全的条目只能形成待核问题，不能冒称完整原配方。

**步骤。**

1. 区分原法、当前实现与拟议适配：逐项说明表示、统计/目标、优化对象、安装顺序、数据预算、推理状态及精度例外的差异。
2. 选真正需要改变的数学对象，定义作用边、轴与编码/解码或补偿关系。方法名串联不是算法定义。
3. 检查组件依赖：变换是否改写邻接权重，补偿是否依赖最终 W，重构是否消费真实量化前缀，共享权重是否出现分支冲突。优先复用现有组件，缺失步骤交原 Coding 链。
4. 在完整父方案上安装实质增量，给出可回退边界。必要时保留同预算简单对照，检验收益是否只来自更多自由度或更多拟合。
5. 将“干预→预期中间变化→任务影响”写成可证伪假设；改变原法关键前提时使用适配变体身份。

**结果解释与下一步。** 浮点不等价先修变换；局部候选单独有效、联合失效，查状态与顺序；复杂补偿与常数偏差修正效果相同，可研究简化；完整组合有价值但归因不明，先保留组合事实，仅在归因改变研究决定时追加消融。

**案例草案。** 将固定偏移表示与新的 W 重构组合。如果 bias 补偿仍按旧 W 计算，失败首先说明组合状态不一致；按所选配方刷新补偿后再评估机制。不能直接宣布偏移方法无效，也不能静默改写原法后沿用原结果标签。

**复用边界。** 浮点等价不保证量化等价；新增 FP 矩阵旁路与可融合偏置的协议归属不同；新架构能否满足 static W4A4 要看实际覆盖边，不凭“结构改变”一词决定。H1/H2 保留完整父状态与回退，H3 可提出手册外机制。

**来源。** 现有 `adapt-quantization-method`；`04_RESEARCH_WORKFLOWS.md` §1、9、11；[NoisyQuant](methods_representation_distribution.md#noisyquant)、[QwT](methods_reconstruction_metrics.md#qwt)、[RegCache](methods_representation_distribution.md#regcache)。原法方程/预算读对应方法材料，本文只提炼组合判断。

## 3. design-scale-calibration：分开候选空间、搜索器与重构调度

**触发。** 已知要拟合什么，需要设计 scale/zero/codebook 候选、共享组、粗细搜索、有限联合更新或重构次序；加密搜索没有带来预期收益。

**前提与范围。** 已有评价目标或可先采用明确的临时目标；知道当前协议允许的推理表示与离线更新对象。优化器步数、候选评估和数据呈现都属于成本。

**步骤。**

1. 分开四个对象：最终推理粒度、校准共享组、评分/重构范围、更新调度。block 调度不自动意味着联合 block reconstruction。
2. 恢复初值、合法域和真实码本；倍率相对哪个 base 明确固定，zero 按实际编码定义。零初始值不能靠纯乘法开启新范围。
3. 判断瓶颈是候选池没有好解，还是生成/选择过程找不到。对已有好解可先做受限投影诊断；投影使用参考答案时不当作独立选参成功。
4. 固定表示与目标比较搜索器，或固定候选池比较目标。FPCS、显式网格、进化搜索比较实际候选数及准备成本，不能让“同一倍率网格”掩盖不同码器。
5. 若使用有限重构，明确阶段更新对象、输入上下文、优化停止点及重校准时机。保留硬量化状态，观察拟合与独立确认是否分离，再决定扩大单元、数据或预算。

**结果解释与下一步。** 好解不在池中，改自由度/候选生成；好解在池中但选不中，转目标选择；增加步数只改善校准误差，考虑数据覆盖、扰动或缩减自由度；前缀改变后旧选择失效，研究重估和顺序。

**案例草案。** AdaLog 原表示在同一实际候选池上并未优于现有配置，而完整 FPCS 更快找到好状态。应把结果归到搜索效率，而非将全部收益归给对数底数；若增加搜索预算后差异消失，可研究更廉价的候选生成。

**复用边界。** 不固化统一 optimizer、步数、组数或搜索网格；I&S 等阶段性配方不能改成所有参数同时 Adam 后仍称原法。有限校准 PTQ 可以保留优化结果；只有额外声称独立无优化规则时才需要独立重建。

**来源。** 现有 `design-scale-calibration`；`04_RESEARCH_WORKFLOWS.md` §2、6；[AdaLog](methods_representation_distribution.md#adalog)、[I&S-ViT](methods_reconstruction_metrics.md#is-vit)、[QDrop](methods_reconstruction_metrics.md#qdrop)。

## 4. select-calibration-objective：检验目标是否能选中好方案

**触发。** 要选择或修订校准目标、参考输入、token 聚合或 lookahead；代理分数变好，实际所选候选却无收益或跨任务冲突。

**前提与范围。** 明确正在排序的决策：单 scale、组、联合编码器、block 或整网候选。候选无有效自由度时先回到构造设计，复杂 loss 不能补足不存在的候选。

**步骤。**

1. 定义目标的完整语义：观察对象、输入/参考状态、实际后缀精度、前瞻单位、误差形式、按样本/token/任务的归一化。不能只写“用 Hessian”。
2. 依据失配选择少量目标：输入编码与实际投影不同，就看运算输出；attention 路由与 V 误差分开时，区分 `ÂV` 和 `ÂV̂`；局部与后缀冲突时，使用已支持的真实量化 lookahead 或任务相关 tap。
3. 敏感度目标绑定父状态、损失、梯度位置、扰动与数据。教师/学生完全相同时 KL 一阶梯度可能为零，应保留数学事实；改损失或扰动属于不同定义，不能用静默 fallback 伪装原指标。
4. 有排序疑问时，冻结同一候选池和选择样本，比较目标选出的状态，再在独立确认数据上评价选择 regret、明显误选与稳定性；同时记录准备和评分成本。
5. 简单目标已经足够时采用它。复杂目标只对某种候选族有效，就保留具体触发条件，不推广成全局默认。

**结果解释与下一步。** 相关性提高但选中方案更差，先看真实误选；所有目标分不开候选，检查信号与候选差异；分类选择改善但 ADE 受损，检查空间 readout、聚合与任务协议，不事后改权重宣布胜出。

**案例草案。** 固定一个 block 的少量合法候选，用局部 MSE、现有 AV/多 tap 目标及已实现的敏感度目标各选一次。确认集只支持前两者，就保留后者未奏效的范围；不据此声称所有 Fisher 方法无效，也不为“新 metric”重复造已有 AV 算子。

**复用边界。** Fisher、Hessian、普通协方差/PCA 不能只因都出现矩阵而互换；pool 最佳值只是该池该视图的参照；小样本任务同分不证明等价。目标更新与候选搜索分工，不要求逐轮跑全部指标。

**来源。** 现有 `select-calibration-objective`；`metrics_registry.md` §4–7；[APQ](methods_reconstruction_metrics.md#apq-vit)、[APHQ](methods_reconstruction_metrics.md#aphq-vit)、[FIMA-Q](methods_reconstruction_metrics.md#fima-q)；既有 `knowledge/research-skills/research-routes/ptq4dino.md` 中候选覆盖与排序反例属于人工历史，数值须沿其原件范围解释。

## 5. design-discriminative-experiment：让测量改变科研决定

**触发。** 两个解释都能说明结果，方法与预算/数据混杂，H3 需要最小可证伪原型，或不知道下一项实验是否值得做。

**前提与范围。** 明确下一决定。若无论结果怎样都执行同一动作，应检查实验是否仍有实现核验或最终评价价值；没有就省去。

**步骤。**

1. 写出主解释与最重要竞争解释，以及它们预测不同的可观察量。允许理论启发，不虚构已有 profiling。
2. 选最少必要对照：固定父状态单因素、一个需要的交互臂、参数交换、同预算简单机制，或独立数据确认。只有交互本身影响判断才扩成因子设计。
3. 对齐能改变结论的条件：源模型、数据用途、初始冻结状态、优化自由度、候选池、总成本和任务目标。无法对齐的部分如实保留，历史比较仍可描述但不作单因素因果证明。
4. 沿现有实验入口声明干预、控制、观测和结果分支。先用数学/局部试验否定明显错误，再按剩余问题升级；已足够接近真实任务时也可直接做适当开发评价，不强制逐级打卡。
5. 回执到达后先核实测到了什么，再解释支持、反对、低信号或仍混杂；选择继续、修订、简化或暂停。

**结果解释与下一步。** 新方法与同预算简单对照相同，研究复杂部分是否必要；多步优化仍不改善而少量新图有效，转数据覆盖；只改变局部 loss 而下游无响应，缩小主张；执行失败先定位工程原因。

**案例草案。** 补偿加上更长重构取得收益，但尚不知贡献。若下一步是决定是否保留补偿，只需同一父状态下的“原预算补偿”和“匹配预算无补偿”等能回答该问题的对照，不要求把所有方法组件拆成完整矩阵。

**复用边界。** 不以统计显著性、实验次数或全网扫描作为所有假设的统一门槛。局部 FP 干预可以用于定位，但不能冒充最终量化候选。相同评测清单不保证校准过程可比。

**来源。** 现有 `design-discriminative-experiment` 及其 `references/experiment-patterns.md`、`decision-examples.md`；`04_RESEARCH_WORKFLOWS.md` §2–6、9、11；该通用流程不冒称某一论文独有方法。

## 6. learn-from-reference-solution：从较好解发现可执行规则

**触发。** 想知道现有表示是否容纳好解，哪些自由度承载收益，或高预算 PTQ 能否提炼为更廉价规则。例行复现和普通 scale 拟合无需先构造参考。

**前提与范围。** 参考来自已核定 PTQ、允许的有限校准优化、解析/高预算搜索或已有人工合法方案；QAT 不作为本技能的参考来源。参考具有可追溯的初态、更新对象和数据，不能称全局最优。

**步骤。**

1. 确定参考回答的具体问题：表达空间、候选覆盖、参数模式、选择能力还是组合效应。已有参考足够时直接使用，不默认重新优化。
2. 对照原状态观察相对尺度、zero、硬码字、分组和功能响应。绝对 scale 差可能仅反映输入幅值，统计模式需与输出作用联系。
3. 需要时用交换、投影、共享/拆组或撤回对照辨认哪项结构承载收益。按参考答案投影属于 reference-assisted 诊断，不证明独立选择器能找到它。
4. 形成可执行规则，写清在新模型/样本上如何从许可统计生成参数和组。若主张不依赖参考优化，就从参考前状态重建，不能读取其逐实例答案。
5. 如果最终算法本来保留有限校准优化，则如实作为 PTQ 配方报告其数据、目标和成本，不强迫丢弃合法优化结果，也不冒称无优化。

**结果解释与下一步。** 小候选族已能容纳好解却不能自主选中，转目标选择；低维投影保留收益，研究共享/简化；模式随模型变化，保留条件规则；重新构造失败，回到规则依赖而非把 reference-assisted 数字当成功。

**案例与边界。** 既有 PTQ4DINO 人工路线中，“参考状态→候选覆盖→选择反例→独立前向分组”是可复用思路；不同日期、自由度和数据子集不能拼成当前 QAViT 的连续成功曲线。本次只读应用内案例，未重读其全部外部原件或重新运行。具体历史阶段能否作为新实验起点，应按当前 PTQ 协议与实际来源核定，不能凭标题中的 STE 一概许可或一概否决。

**复用边界。** 不从成功快照复制逐模型参数后声称发现通用规则；不把参考更好当作原方案根因已确定；“学习参考”是科研活动，不自动创建新 Skill。

**来源。** 现有 `learn-from-reference-solution` 与两份 references；`knowledge/research-skills/research-routes/ptq4dino.md`；`04_RESEARCH_WORKFLOWS.md` §2、12。旧文中的统一 training-free 限制需改为本节对最终方法真实依赖的区分。

## 7. evaluate-ptq-candidate：从证据决定投入与主张范围

**触发。** 已有局部或完整结果，需要判断机制、任务收益、跨任务冲突、后续投入或正式验证范围。单纯归档和例行执行不需要重新评判全史。

**前提与范围。** 恢复确切候选/对照版本、实际协议、任务目标、评价视图与成本；只补会改变判断的缺口。

**步骤。**

1. 分开回答：测量是否有效、机制得到何种支持、任务有何价值、能否迁移。工具失败、计划和文献成绩不作为本地反证或成功。
2. 依比较意图检查条件：原法复现保留原设置；机制对比尽量保持量化条件；资源研究按真实存储/计算/延迟；迁移研究保留源域、目标域与任务头信息。不同意图不压成同一个裸分数。
3. 同时解释 FP、Q、Q−FP、单位和实际样本。双任务方向相反时按当前 Brief 的目标裁决，保留另一任务信息；不事后只报告有利指标。
4. 比较 B 时使用相应 before_l3 快照，避免候选已晋升后误判“没有新方案”。独立 B、开发阶段和官方阶段分别保留来源。
5. 选择继续、修订、暂停或转正式验证，并说明下一动作将解决哪项未知。三条已提交最终候选仍保有既定 L3 机会，局部代理不淘汰其中两条。

**结果解释与下一步。** 局部/任务一致且方案完整，进入相应验证；局部改善而任务下降，优先检查目标与传播；有效负结果可停止具体机制；只发生工程问题保持未验证；预算不足保存当前成果和具体续做入口。

**案例草案。** 一个 mixed 候选取得较高 mIoU，另一个是固定 W4A4。先看问题是否允许 mixed 及资源条件，分别记录结果；不能直接把前者晋升为 static W4A4 B。若目标是给定存储预算下最高 ADE，重新形成该资源口径内的比较，而非改写旧标签。

**复用边界。** 完整量化构造、开发视图完成、官方数据完成、部署加速是不同证据层级；低成本集成通过不能支持真实精度收益。只读已有官方成绩后做出的选择，应保留开发接触历史。

**来源。** 现有 `evaluate-ptq-candidate` 与 `references/evidence-and-comparison.md`；`01_STATIC_W4A4_V2.md`、`02_PROTOCOL_PROFILES.json`、`metrics_registry.md` §7–10；`04_RESEARCH_WORKFLOWS.md` §12。

## 8. choose-ptq-calibration-data：分离数据覆盖与恢复算法

**触发。** 真实校准数据不足/不可用，扩大样本、多视图或合成图带来变化，或源域构造后迁移任务下降。单纯按既定清单加载数据不需要本技能。

**前提与范围。** 明确数据许可、监督信息、任务模式和恢复器；data-free 的生成与下游恢复都必须符合 PTQ。方法本文只确认 A8 时，改为 A4 是新验证范围。

**步骤。**

1. 清点真实数据用途：独立图像、视图/窗口、反复呈现、生成、敏感度、选择和评价。校准“32 图”不覆盖另用的大规模重要度估计或搜索数据。
2. 固定恢复器与预算比较真实图、噪声、所选合成/覆盖策略；固定数据再比较恢复目标。不要同时更换生成器与量化学生流程后把收益全归数据。
3. 查看模型内部覆盖：量化范围、patch 关系、attention 及任务相关读出，而非只评图像外观。生成器需要类别头而当前只有 dense 读出时，修改目标要作为新变体。
4. 分别计算生成、教师 forward/backward、搜索和有限重构成本。样本更多、呈现更多和更复杂恢复属于不同投入。
5. 按问题选择源域迁移、联合校准或分任务包，明确其主张范围，再将冻结结果交独立确认。

**结果解释与下一步。** 更多同类图无益但结构覆盖有效，研究选择/生成目标；仅目标域数据有效，缩小单源迁移主张；合成图只有配套重构器下有效，检查交互；校准损失下降但确认变差，检查覆盖与过拟合。

**案例草案。** 以同一有限 block PTQ 恢复器比较 PSAQ 风格合成与 SARDFQ 合成来源，保存各自生成预算；再选择是否研究恢复器。若不是作者原配方，标为组件实验，不将它写成完整原法复现。

**复用边界。** 多窗口不算独立图；合成图片更新不等于网络 QAT；data-free 标签也不能为量化学生完整训练提供许可。DINO register 与 patch 的处理从实际布局确定。

**来源。** `04_RESEARCH_WORKFLOWS.md` §8；[PSAQ-ViT](methods_data_free.md#psaq-vit)、[CLAMP](methods_data_free.md#clamp-vit)、[SARDFQ](methods_data_free.md#sardfq)、[DAQuant 的原机制边界](methods_representation_distribution.md#daquant)。本节不把 DAQuant 改称样本选择算法。

## 9. allocate-ptq-precision：在真实预算下研究静态或动态分配

**触发。** 各层/token/窗口敏感度不均，固定预算下需要精度分配，或动态分组/格式选择的收益与成本不清楚。

**前提与范围。** 当前 profile 允许相应自由度，并定义共同任务目标和资源度量。固定主线下可使用敏感度作诊断，但不能暗中提高某些边的 bit。

**步骤。**

1. 定义决策变量：离线 layer bit、格式、固定组，或输入相关 scale/group/bit 路由。动态 scale、动态分组和动态 bit 是不同算法。
2. 取得与本问题匹配的质量—成本响应，记录敏感度所用父状态、数据和准备成本；方法中的全数据统计不能藏在少量校准标签后。
3. 选适当求解器，如贪心、ILP 或 Pareto；保留原算法和约束。预算用实际权重/激活规模、元数据、例外、分支和必要重排计算。
4. 每次更新后重算真实预算及完整配置。LampQ 论文的异规模层一加一减不必然保持参数量加权预算，不能仅据文字声明通过；自行修复应标变体。
5. 对动态策略先区分输入依赖价值与更多组数/更高平均精度，再计入运行统计、路由和 packing。缺 kernel 时先保留算法证据，部署收益另测。

**结果解释与下一步。** 静态分组已稳定有效，研究更简单规则；跨输入敏感位置变化大，才进一步研究动态；平均 bit 看似相同但真实成本不同，先修比较口径；理论 BOPs 降低却无速度，转部署路径。

**案例草案。** window-based 模型上，比较 MixA-Q 独立 PTQ 分支与相同资源条件的统一激活精度。窗口路由不能直接移到全局 attention 后仍沿用原法证据；若需要迁移，先定义分组与共享权重规则。

**复用边界。** AMP/MPTQ 共用家族，不能作为两份独立验证；TokenDynamic/OptimalFormat 原配方尚未闭合，不能启用“已复现”执行；向量码本索引 bit 不等于 scalar WbAb。混精度与动态原法保持各自 profile。

**来源。** `04_RESEARCH_WORKFLOWS.md` §7、10；[AMP](methods_precision_allocation.md#amp-vit)、[LampQ](methods_precision_allocation.md#lampq)、[MixA-Q PTQ](methods_precision_allocation.md#mixa-q)、[IGQ](methods_representation_distribution.md#igq_vit)；`research_corrections_coverage.md` 的预算口径。

## 10. validate-ptq-deployment：区分数值表示、算子路径与真实速度

**触发。** 新码本、补偿、重参数化或运行时路由需要导出；整数化导致退化；理论成本下降没有转化为实际速度。

**前提与范围。** 明确目标是数学实现、可重载状态还是指定设备性能。没有目标硬件时可以完成前两者，不虚构 kernel 支持或部署数字。

**步骤。**

1. 从实际执行图列出量化边与状态：码本、scale/zero、分组、补偿、路由、bias、accumulator 及浮点例外。先关注本次新增和依赖部分，不重复全库审计。
2. 用有辨别力的小输入检查边界、零、饱和、总码态、整数范围和变换等价性。H-ViT 式上下界若产生多一个码态，应保留原文疑点与适配记录，不能静默放宽位数。
3. 检查构造后冻结、导出/重载与真实 apply 路径一致；输入 shape/token 布局改变时，明确哪些状态合法复用。位置相关补偿不能未经处理跨分辨率套用。
4. 有真实 backend 时辨认 Q/DQ、pack/unpack、布局、重定标、非线性和 fallback，再测匹配 batch/分辨率下的端到端时间；记录构造成本与运行成本各自范围。
5. 若性能未兑现，定位是表示成本、算子缺失还是调度/搬运；回传具体可简化对象，而非仅增加算法复杂度。

**结果解释与下一步。** 重载后不同先修 artifact；单算子准确但整网下降，查范围与跨算子 scale；BOPs 下降而延迟不降，研究布局/融合；只在某后端有效，保留该条件，不扩为通用加速。

**案例草案。** IPTQ 非线性仿真结果良好，但当前配置的某个 log-family kernel 不支持。可以保留算法研究结果，明确该 route 的 fallback；不能把浮点执行时间解释为 integer-only 速度，也不因部署未完成否认数学近似的已有证据。

**复用边界。** 参考 QDQ 的耗时不是 native 4 bit kernel 的性能；kernel 加速不是整网加速；Approximation Softmax/LN 的 BERT/GPT-2 结果仅为算子旁证；Trio 的 EfficientViT 拓扑不能直接替代标准 ViT。

**来源。** `04_RESEARCH_WORKFLOWS.md` §9–11；[PracticalEdge](methods_deployment.md#practicaledge)、[IPTQ](methods_deployment.md#iptq-vit)、[H-ViT](methods_deployment.md#h-vit)、[Trio](methods_deployment.md#trio-vit)；`metrics_registry.md` §10。

## 11. distill-ptq-research-procedure：沉淀会改变下一次决策的流程

**触发。** Recorder 发现可重复使用的诊断、选择、修复或停止办法；或人工新研究材料补足现有流程。只出现一次成绩、最佳倍率或未执行想法时，通常保留知识/研究笔记即可。

**前提与范围。** 有真实来源和明确的可迁移决策。人工素材、原论文方法学和本批经历都可以提供流程，但需保留不同证据身份；本地经验只用当前可见、可引用的真实记录。

**步骤。**

1. 把经历从“做了某方法”改写为“遇到什么现象，什么证据让下一步改变”。识别触发、前提、关键观察、结果分支和反例。
2. 查当前 Skill 目录的真实正文与版本。已有同义流程时修订触发/分支/边界，而非增加一个论文同名 Skill；没有独立决策价值则不发布。
3. 提炼结构性规则，移除某次层号、倍率、随机 seed 和成功分数等实例答案。保留确有作用的条件，如实际 Q 后缀、数据用途或完整父状态。
4. Recorder 使用现有 skill_updates 合同，绑定本批真实卡片的窄 payload 字段；人工文献种子走资料入口，不能伪造本批来源。修订/停用使用当前可见 base 版本，来源冲突保留原件。
5. 写成条件化的步骤与结果解释。没有支持通用成功的证据时，发布为有来源的研究流程/待验证启发，而非“已验证有效方法”；需新实验的部分交下一轮指导。

**结果解释与下一步。** 新经验只补一个反例，修订现有边界；流程在不同条件反复有效，扩大范围时带上相应真实来源；原判断被反驳，修订或停用但保留历史；工程失败揭示来源恢复错误，可以沉淀恢复流程，不能上升为算法失败规律。

**案例草案。** 一批证据显示局部 NMSE 的赢家在独立确认中更差。可将“同池比较选择 regret，并区分参考输入”补入目标选择 Skill；不能发布“永远不用 NMSE”。如果缺少独立确认，先把观察和下一项检验写入知识与研究指导，不补造结论。

**复用边界。** Skill 不是完整模型包、论文摘要或参数数据库；不得把方法数量、调用次数当科研成功。新种子不能覆盖已有运行发布谱系；有来源的人工流程与 Recorder 流程同等可检索，可信度由实际证据决定。

**来源。** 已读 `core/skills.py` 的 `initialize / prepare / publish / reconcile`、`agents/prompts/recorder.md` 与 `tasks/record.md`；现有 `knowledge/research-skills/` 人工案例；`04_RESEARCH_WORKFLOWS.md` §12。这是现有发布通路上的内容流程，不增加发布工具或新的审批角色。
