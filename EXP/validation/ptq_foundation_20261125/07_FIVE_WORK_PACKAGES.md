# 五个工作包：接入范围、文字依据与完成条件

本文件承接已经确认的五个工作包：A 协议、知识分类与来源账本；B 共用数值基础与完整 PTQ 方法；C metric、任务适配与公平比较；D 研究流程、Skill 与提示词；E 集成与科研能力验证。

本次补全包为这五包提供文字规格，由 Codex 在实际 QAViT 工作区接入并做必要验证。后续综合调优和完整高成本科研运行保持为下一阶段；E 在本轮完成接入层面的真实小规模验证，不自动扩大为多轮完整 ImageNet/ADE 搜索。

## 1. 对上一版材料的审计结论

上一版 20 个文件已经完成协议草案、综述覆盖、方法三层拆解、metric 定义、12 条研究路线和接入方向。它适合用户当时要求的“协议确认＋方法拆解”。但若要让 Codex 完成 A–E，以下几项还需要明确正文。

| 接入问题 | 上一版已有内容 | 本次补充 |
| --- | --- | --- |
| 每篇方法具体依赖什么 | 各方法长文中有组件与差距 | 08 提供全量对应表、共享能力与状态重估关系 |
| Prompt 实际怎么改 | 05 有角色职责片段 | 09 提供与当前角色和阶段对应的可接入正文，并说明替换位置与机械契约边界 |
| Skill 如何成为可用资产 | 04 有研究路线，05 有蒸馏原则 | 10 提供可映射到现有 Skill 格式的具体内容与案例，保留已有身份 |

这些补充不增加论文覆盖数量，不补造原文缺失参数，也不宣称方法已经在 QAViT 中实现。

## 2. 总体范围与两种完成事实

**知识接入覆盖全量已纳入材料。** 51 个综述主条目与 ERQ 后续版本的正文、机制、研究路线、来源及限制均应进入可发现、可读取的知识体系。已有方法更新原资产；别名和后续版本建立关系，避免重复独立 baseline。5 个来源待补齐条目、1 个同家族出版记录、1 个算子旁证及排除记录保持各自身份。

**执行能力按真实实现记录。** 只写文档、给插件起名或通过 schema 检查，都不能称为算法已接入。本轮应实现来源已经足以确定、适合当前软件后端的共享数值组件与完整配方，不得自行把全量目标缩成几个容易的方法。对尚未闭合的公式、参数、架构前提和专用后端，逐条说明具体缺口；能够依据已有原文/代码闭合的继续完成，不能用笼统的“待实现”结束整个能力族。

独立 PTQ 原法、可运行的数值参考实现、特定模型适配、论文精度复现和原生硬件部署分别记录。FPGA 或专用芯片论文不要求在 V100 上重造其硬件；可验证的软件数学部分与硬件证据分开。LLM 或特定混合架构上的原证据，不会因导入文库自动成为任意 ViT 的实证。

QAT 严禁录入。有限校准 PTQ 重构、图像合成时更新像素、只读梯度诊断依据已确认的实际流程判断。不能把优化器出现本身作为 QAT 判据，也不能把完整量化任务训练改名为 calibration。

## 3. 工作包 A：协议、知识分类与来源账本

### 要完成的工作

以 01、02 为新协议语义，检查执行契约、上下文注入、父包重用、实验准备、冻结评价、导出重载和结果核对中的旧规则。`static_w4a4/2` 允许有限校准 PTQ 优化，主配置仍有明确的静态推理和四位编码含义；扩展配置继承全局 QAT 排除。

同步方法目录、来源目录和研究分类。科学主题以问题为单位，分类用于描述主要/配套可变维度与固定条件；不将每轮主题变成互斥类别的机械抽签。目录保留来源状态、适用问题、正文入口和实际实现状态，不能在注入上下文时丢掉状态。

### 必须分开的身份

| 身份 | 代表什么 | 接入规则 |
| --- | --- | --- |
| 文献/配方 ID | 如 adalog、fima-q，定位静态研究材料及版本 | 通过方法目录和正文入口读取 |
| primitive ID | 一个数学操作或共用求解器 | 对应真实数值接口，不能只凭文稿名称声明可调用 |
| 运行 method_id | 本次研究中产生并持续演进的算法谱系 | 沿现有 ResearchTopics 管理；新谱系由宿主分配 |
| candidate_ref | 某次 H 的确切版本 | 证据、Critic 意见及 L3 与该版本绑定 |
| solution_id | 完整可恢复方案及其评价 | 保留比较条件、包状态和适用范围 |
| topic_ref / inspiration_id | 研究问题与尚待发展的构想 | 独立接续，不由方法名称相似度合并 |
| Skill 名称/版本 | 可复用的决策过程 | 沿现有人工种子与 Recorder 发布体系维护 |

在本次源码基线中，`context.method_catalog` 来自 `docs/methods/index.json`，静态正文通过 `read_asset` 的 `methods/<document>` 读取；`read_method` 处理运行产生的 method_id 谱系。二者不要因同叫“方法”而混用。字段名可以按实际架构调整，身份含义应保留。

### 完成依据

新旧协议能按各自版本恢复；新的合法优化型 PTQ 不会被隐藏的 training-free 旧条件拒绝。83 条来源逐条有去向；QAT 与训练边界未决记录不能进入可生成的算法正文。Generation 能从短目录找到相关长文，并获知其真实实现状态。

## 4. 工作包 B：共用数值基础与完整 PTQ 方法

### 要完成的工作

以所有 methods 文稿、existing_methods_delta 与 08 为依据，先梳理共享能力，再组装完整原法。共享设施包括量化表示与固定粒度、等价变换、搜索与分配、有限校准重构、补偿、数据生成、结构适配及其保存/加载。复用现有 GPTQ/GPTAQ/AdaRound、变换、calibration、frozen_trials、propagation 等，补其实际缺口。

一个完整 recipe 应能描述有序阶段、每阶段输入和参考、更新对象、目标、原配方预算、例外、依赖统计及最终状态。组件顺序可以研究，但改变顺序后需要重估什么由数学依赖决定。例如改了 LN/Linear 表示，后续 W 网格、输入统计和曲率不能默认沿用旧状态。

作者论文与代码有差异时分别保存来源配置。实现所需的数值修复、静态适配或目标改变建立新变体，清楚说明差异。可以修复作者代码的样本对齐、空集合、数值求解等工程问题，但不能把修复后的结果暗写成逐字复现。

### 对能力覆盖的要求

08 的每条记录都要落到以下事实之一：已有能力已复用并核对；新增组件及配方已实现并通过相应小规模执行；来源或数学定义有明确未闭合项；原法依赖当前未覆盖的架构/后端而保留相应材料及可复用组件。最后两类须具体到缺什么、影响哪一阶段、下一步如何关闭，不能作为默认收尾状态。

当前接口对激活 per-token/per-group 的 dynamic 限定、冻结候选只接收局部 scale 编辑等，都可以按新需求调整。研究空间由已确认协议和数学定义决定，不能继续用旧容器表达能力不足否决新方法。

### 完成依据

新增可执行能力通过实际公共入口运行；准备结束后能够导出、独立加载并恢复预期图和数值状态。完整配方有可追溯执行顺序，不能用只实现一项 loss 或 quantizer 冒充整套原法。缩小数据/迭代的执行检查单独标为验证配置，不覆盖作者原配置，也不充作论文精度复现。

## 5. 工作包 C：metric、任务适配与公平比较

### 要完成的工作

以 metrics_registry 和 11 为依据，将 metric 的数学定义、准备步骤、评分和使用场景接入同一体系。保留已有基础评分器，增加其缺失的观察和目标，支持完整模型候选。记录 reference、输入状态、任务/head、轴、归约、温度/扰动/秩、成本以及缓存失效条件。

任务适配读取真实模型 metadata、token 布局、窗口和 mask。当前分类梯度路径不能仅靠给 dense 张量换一个名称就扩成密集任务敏感度。支持协议允许的数据/任务模式，并在结果中区分同包迁移、联合构造和分别构造。

比较条件由本轮研究问题确定，不按候选所有实现参数完全相同分桶；同时不能把不同精度覆盖、数据许可、head 或评价视图的成绩无条件混排。主任务选择、保留率和资源目标由配置决定，保持现有运行既定目标及历史结果原义。

### 完成依据

同一候选池可比较不同 metric 的选取结果，而不仅比较 metric 数值；能解释局部改善是否保住传播后表征与任务表现。缓存不会跨不兼容状态误用。优化型 PTQ 的冻结父方案可按实际配置继承；原有方案、B、灵感与历史证据不丢失，不因改协议而自动变成新协议成绩。

## 6. 工作包 D：研究流程、Skill 与提示词

### 要完成的工作

使用 04、05、09、10 的正文，更新真实活跃角色及其任务片段、方法/Skill/研究案例的检索和 Recorder 沉淀。以当前 generation_critic 流程为基础，保留 H1/H2 的完整父方案改良、H3 灵感接续、独立 B 和三候选正式评价。具体角色分工按当前源码，停用角色不重新引入。

写作上直接使用提供的研究正文。Codex 负责目录、占位符、真实字段和接口引用的机械适配；确有语义冲突时依据新协议和实际源码修正，并记录修改理由。不要重新用几句泛泛摘要替代方法长文或关键实验步骤。

Prompt 保留职责、当前任务和按需入口。方法细节与案例留在知识资产，必要时完整读取。目录、正文和当前能力保持对应；未实现方法仍可被发现，但不能冒充已注册工具。

Skill 描述可复用的决策过程。已有 Skill 可增补引用和反例，不必每篇论文新增一个 Skill。人工材料与 Recorder 蒸馏材料进入相同的检索和版本体系；来源不同不决定其科学结论真假。

### 完成依据

能从真实问题检索到相关正文和 Skill；角色实际输入不再带入与本轮冲突的旧常规禁令。Critic 能指出有证据的数学/比较问题；Recorder 能保存条件、反例和下一步；后续任务能恢复确切经验和未完成动作。这里验证的是可用行为，不以 Skill 调用次数或新增文件数代替科研能力。

## 7. 工作包 E：集成与科研能力验证

### 要完成的工作

按 12 将高价值情境并入已有低成本评价和回归设施。覆盖文稿路由、真实数值调用、导出重载、任务/比较身份、角色协作、Recorder 与跨轮恢复，确认新方法实际进入研究链。选择验证规模以足以暴露具体问题为准，先用现有 fixture 和小规模真实模型路径。

算法检查与角色行为检查分别给证据。mock 可以验证调度和失败恢复，不能证明数值方法已经实现；静态字符串检查不能证明角色会正确使用材料。至少完成代表不同执行机制的真实准备—保存—加载—评分路径，以及一次覆盖相关角色和记忆恢复的小规模链路检查。具体方法的“可执行”声明还应具有对应执行证据，不能只用一个代表方法替所有接口背书。

若验证暴露的是本轮新增内容未接通或语义错误，继续修复并重查；不要扩展成无边界的 agent 调优。低成本验证结果单独标记，不写成正式 L3 成绩，也不自动触发全量数据或多轮科研搜索。

### 完成依据

每个工作包有改动、实际行为、验证证据及剩余限制；失败能够区分来源不足、算法不适用、实现问题、宿主问题与资源问题。保存后续综合调优和完整运行的入口、配置需求及未决事项，本轮不执行那个阶段。

## 8. 不应在接入时丢失的既有能力

当前机制中，Generation 自主实验、Critic 加强后由 Generation 决策、三候选各自 L3、独立 B、完整父方案与回退增量、方案库/灵感库分离、动态主题、确切版本恢复、Recorder 的 Skill 版本化、候选优先分卡及按需上下文，均继续发挥作用。新增文库不得把研究变成固定方法菜单或由监控 Codex 代做选题。

模型由用户指定，算法适用性从模型 metadata 与真实计算边判断。DINOv3/ADE 是当前重点实例，不能变成宿主唯一可处理的结构；其它论文的 DeiT/Swin 超参数也不能自动成为全局默认。

必要的跨组件修改应一次配套完成。以科研效果为依据调整接口和组织结构，同时避免与本轮目标无关的系统重写、新审批阶段和重复评价平台。

## 9. Codex 的最终交付

交付五包完成表、方法/组件的真实能力清单、关键改动和验证证据、必要的来源/实现差异，以及后续阶段的明确入口。对仍未完成的项说明原因与影响，不将其混入“已实现”；对已经完成的接口给出实际调用、保存/重载和评分证据。

文字材料齐备、实现覆盖、数值正确、研究行为有效和最终任务精度提高是五种不同事实。本轮推进前四项，为后续完整研究验证第五项准备可靠起点。
