# gonly QAViT 工程补全与断点评测报告

本次修复涉及三条会影响科研判断的链路。普通自定义诊断可以按声明的子视图取图，已评价的自定义包可以按原身份跨轮冷载，Coding 可以直接使用宿主给出的父源码句柄修订并提交。一次独立短链用新实现完成了 12 张图的真实测量。随后 Generation 收到了同一份观测，提出了另一个可区分机制的实验；该提案保留为未测。另一次真实 H1 断点回放中，Generation 识别出旧四臂实验没有测量，按新接口重新提出保留原有序子视图的实验。

### 评测集合与原始依据

- [断点清单](collection.json) 从现有 Eval-L0 的 115 个真实角色任务中选了 12 个调用起点，10 个开发、2 个保留。每个条目记录原任务和尝试号、来源哈希、read view、输入版本、可用工具、职责、验收依据，以及调用和任务两种成本。选择单位是决策点，一个多步任务可以只取其中一步。

- 初始化、运行段人工干预、三轮检查点、收尾和官方评价另保存在同名 `EXP/inputs/` 下。开发使用固定 5,000 张 ImageNet 与 502 张 ADE 数据。官方评价前已在新候选中按双任务最小 FP 保留率选择，`official_results_seen_at_selection=false`。原官方 P64 包（`cb02fd77…`）在 50,000/2,000 样本上为 **60.018% Top-1、29.1340% mIoU**，对应 FP 为 **79.128%、52.8578%**。本轮没有新增官方或完整 L3-dev 成绩，距离 71.2152% 和约 47.5720% 的目标仍需科研改进。

静态检查覆盖 218 个 Python 文件，结构审计通过；知识审计覆盖 81 页、7 个 Skill 和 21 个方法。固定工作树的 370 项 CPU 回归全部通过（534.22 秒）。最终监控器补丁后，运行时组 48 项和另外两个监控用例均通过，后者分别检查无需派工时不启动子进程，以及截止时停止真实 CPU 子进程。各口径包含重复用例，不将它们累加为独立覆盖数。[验证记录](verification.json)

同一 H1 起点在历史上改问了两个可部署的 V4 尺度倍率问题，分别看 CLS 与 patch。新版选择继续原先受阻的 P/V 四臂干预。这两条决策各有科研理由；本次可以确认已暴露的视图能力被新版正确使用，无法据此比较两条路线的精度收益。

### 按组件复用

以下命令从项目根运行。默认只需 CPU。输入资产、权重、受限的原 CLI 记录与冻结对象留在服务器；轻量索引可纳入版本管理，离开服务器复现实测须提供对应哈希的资产。

```bash
V=EXP/validation/engineering_replay_20261122
R=dinov3b_static_w4a4_independent_20261121_r1
export PYTHONPATH=QAViT
python -B "$V/verify.py" data frozen
python -B "$V/verify.py" source knowledge
python -B "$V/verify.py" generation runtime evaluation
python -B "$V/verify.py" all
python -B QAViT/tools/evaluation verify "EXP/evaluations/$R"
python -B "$V/audit.py"
python -B "$V/evidence_index.py"
```

`verify.py` 对重复模块去重，关闭可见 GPU；按对应组运行即可。Eval-L0 的历史评分、成本和报告沿用原入口与 gonly_v0_3。需要新行为采样时才运行下列命令，输出名须为新的 evaluation 同级目录，原件只读。第二步以第一次实际提交的 artifact 为输入，只在新审查批准且仍是原 12 图局部请求时运行对应真实 worker。当前实际数值脚本使用本机 GPU 1，单图脚本的 CUDA 可见设备须与保护设备号一致。

```bash
python -B QAViT/tools/evaluation/breakpoint.py "$V/collection.json" code_repair \
  --turns 2 --output EXP/evaluations/my_edit_01
python -B "$V/chain.py" EXP/evaluations/my_edit_01 EXP/evaluations/my_chain_01
CUDA_VISIBLE_DEVICES='' python -B "$V/package_probe.py" --data-only "$V/my_decode_01"
CUDA_VISIBLE_DEVICES=1 python -B "$V/package_probe.py" "$V/my_one_image_01"
```

保留案例仅在独立评测时用 `--held-out` 显式开启，本轮两个均未采样。断点仅使用起始 request 的当时输入、消息、权限和父版本，叠加当前角色 Prompt、Schema 及可从父原件确定的句柄。离线回放当前可实际服务部分已固定文本读取、受控编辑和提交。选择其他研究工具时记录实际选择及 unmeasured；不会将相近实验映射到旧结果。实际失效、不同参数及不同父状态也不得移植结果。评阅方可比对本次新分支和旧轨迹，评分标准、后轮信息、原任务在该断点以后的回答均不得加入 actor 输入。

### 当前流程伪代码与结论边界

```text
每轮 Generation 在冻结 Brief、B、可见父方案、灵感与 Recorder 反馈上选择课题
H1/H2 改良各自完整父方案；H3 恢复并发展灵感
有研究问题 → 冻结原请求 → Coding 按父哈希修订 → Safeguard 审当前版本
获批 → 在绑定视图和冻结来源上执行 → 验收实际读取/状态 → Evidence 回到请求者
Generation 综合、必要时修订 → 三个最终候选各自进入既定 L3 → 收有效结果
Recorder 沉淀建议 → 下一轮按 read view 恢复；停止时接受晚到回执并幂等保存
```
