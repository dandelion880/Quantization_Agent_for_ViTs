# 科研决策回放与交接

本轮改的是下一次科研决定可用的依据。真实回放中，前后两版 Generation 都识别了局部代理失配；新版在一次共同选题中收窄了同时探索的自由度。现有证据足以确认回送可用，单次选题差异不足以估计决策质量的平均提升。

## 调用链与修改

- 从 `QAViT/run.py` 进入 Workflow，轮初 focus 先恢复主题与灵感，H1/H2/H3 生成、实验、接收 Evidence 后可修订；select 绑定三个最终版本，分别 plan_l3、执行，再由 Recorder 复盘。该链已有完整方案库、独立 B、判别实验 Skill 和已授权原件读取。L3-dev 的隔离、校验与开发成绩归档，以及 Coding/Safeguard 的单实现、工程修订和审查均沿用既有入口。
- 完整候选成绩原可在方案目录、Recorder、轮末事件分别找到；已有 Recorder 时，下一轮常规 focus 并未直接绑定逐候选 L3 证据。现在 focus 和 generate 从上一个已关闭轮次投影确切候选、父方案与干预、完成状态、实验和 Evidence 引用、实际校准数和样本身份（有记录时）、评测范围与配对 FP/Q；已随其他来源送达的测量只给定位。没有轮末候选绑定的旧记录沿既有读取路径处理。历史局部实验按发布顺序给出研究问题和对照入口；有记录的逐臂配对差与标准误进入摘要。科学解释继续由 Generation 作出。[上下文](../../../QAViT/agents/interaction.py) · [测量投影](../../../QAViT/core/evidence.py)
- focus 按模型读出、全局依据及未决问题选少量关联的可变维度，保留继承配置、范围复议条件。generate 要把局部发现落实到可回退父方案，并交代传播与双任务尚待检验之处。七项 Skill 继续按需读取；修订诊断、判别实验、参考解和候选评价的策略，加入依据 PTQ4ViT 与 PTQ4DINO 区分“候选是否覆盖”和“评分是否选中”的案例，避免重复建设。[主题指令](../../../QAViT/agents/prompts/tasks/focus.md) · [Skill 目录](../../../QAViT/docs/skills/INDEX.md) · [案例与原文](../../../QAViT/docs/skills/design-discriminative-experiment/references/decision-examples.md)
- 新 DINOv3-B 独立开发输入直接绑定已有 B32/H1 开发成绩文件及哈希，注明校准样本差异。开发图上两包 Top-1/mIoU 分别为 57.78/33.1328 和 61.38/34.0804；历史官方分割结果分别为 29.6848 和 28.9541。开发增量不能归因为单独的 FC2 规则。同一最终冻结骨干在完整官方验证集一次测得的两个保持率才用于核对 90% 目标。[输入](../../inputs/dinov3b_static_w4a4_independent_dev/input.json) · [已有实测](../l3_dev_20261120/facts.json)

## 决策断点

| 断点 | 改前 | 改后和证据解释 |
|---|---|---|
| 首轮共同选题 | 真实历史 focus 同时开放 W/A 边界、码本、分组、重参数化、误差补偿、拟合顺序及读出。 | 使用历史 focus 的原始输入、相同请求模型与工具，选择关注两条残差写回路径的 A4 选参；用同候选集合区分表示容量与排序，保留切换分支和层段的条件。两条路径仍是模型结构启发的假设，尚未定位全局瓶颈。[旧输出](before/focus/focus.json) · [新输出](after/focus/focus.json) |
| B64 相同父状态，局部 E₂ 下降，后续读出方向不一致 | 实时旧版认为九项配置可区分局部改善与传播，选择校准目标 Skill；收到测量后提出复核 KL 门槛的独立作用。 | 实时新版也采用确切冻结设计并选择同一 Skill。收到结果才指出 (0.7,0.7) 的局部改善未传到 E₅，KL 与小样本 Top-1 也不同向。它写明完整 B64 继承项、倍率规则和撤销方式；所选状态恰为身份，继续检验门槛，不把身份当作 H1 新收益。两版实际用了该 Skill 的同候选池、相同背景、配对评分思路，未隔离 Skill 的因果贡献。[旧设计](before/local/design.json) · [旧判断](before/local/receipt.json) · [新设计](after/local/design.json) · [新判断](after/local/receipt.json) |

局部断点采用受限决策回放。第一步可接受已有设计或另提行动，只向采用原 ExperimentCard 的回答返回匹配的真实结果。两个版本均实际选择了原设计；第二步接收所选 Skill、具体臂指标、选择器与样本数。两个版本均未提前收到后续选行结果、完整候选成绩或人工结论。这是在真实模型上的设计取舍与反馈验证，重新派发实验的完整宿主链另由原运行实录核对。选题回放沿历史 Brief，因此其中对官方评测时机的描述属于旧任务输入。

原运行本身给出了开放式“请求—实测—修订—完整候选”轨迹：H1 的自主实验请求与数值 worker 的 original_request 完全匹配。收到局部反例后，Generation 改测同一完整父状态上的 W4 舍入；随后在 patch 与 CLS 的取舍中提出双条件选行，经历父包来源修复，最终提交部分 FC2 输出行替换及 packed W4 回退规则。search1000 的局部与下游改善仍未提高分类命中率。历史原件仅用于对应时点或事后核对。[原始请求](../../runs/dinov3b_static_w4a4_gonly_next4_20261118_r1/jobs/task-58d6bc5168e8764318ea3ebe-a0002/result.json) · [改测请求](../../runs/dinov3b_static_w4a4_gonly_next4_20261118_r1/jobs/task-58d6bc5168e8764318ea3ebe-a0004/result.json) · [最终提交](../../runs/dinov3b_static_w4a4_gonly_next4_20261118_r1/jobs/task-58d6bc5168e8764318ea3ebe-a0010/result.json)

回放后的原件核对也回答了模型提出的问题：去掉 KL 门槛，九项中校准 E₅ 最小的是 (0.7,0.7)，K 为 0.751934，高于身份门槛 0.736046。门槛实际改变了选择；这并不建立它对分类或分割的收益。64 图 search 的 E₂ 配对差为 −0.01243（标准误 0.00137），E₅ 为 +0.00152（0.00166），KL 为 +0.02643（0.04611）。后二者只宜报告样本方向。新版模型准确指出回放摘要缺少配对标准误，由此补修了臂摘要并逐值比对原件。五次模型预算已用完，这个最后修补仅做原件和接口核验。[核对结果](projection.json) · [门槛复查与调用记录](calls.json)

## 验证与边界

- 五次真实订阅调用均请求 gpt-6.2-astra/high，CLI 0.171.0 未回显实际模型与档位。累计输入 89,581、输出 4,610 tokens，单次耗时 19.0–47.5 秒，无 GPU 派发。首次预检触及正式运行的 96% 预留线，未调用模型；后续按用户授权使用独立验证预算。局部前后使用相同历史设计与臂数据，选题改前复用历史输出；跨时间服务差异、采样与相近提示词都限制了归因。[回放入口](replay.py) · [调用收据索引](calls.json)
- 用只读 Workflow 复核真实轮末三个候选的绑定、64 图校准及两个完整官方任务原值。提交前无下一轮投影，提交后的三条合计 7,028 个 canonical JSON 字符。另一份真实开发 Journal 分别核对 5,000/502 张、complete_view、开发集身份及两包 FP/Q。新研究输入通过配置检查。42 项定向 CPU 测试覆盖实验回送、主题、Skill 发现与原件读取、开发视图和提示词；七项 Skill、21 项方法、81 页通过知识审计。历史 Coding/Safeguard 的紧凑上下文测试现核对按原引用读回执行条件，并同步了已提交的角色提示词快照。[核对脚本](verify.py) · [测试结果](verified.log)
- 初试复用旧三候选排队夹具时，其 evaluate_artifact 草案缺冻结模型包，被现行绑定检查拒绝。保留这条检查；改用独立合约夹具测试部分/空结果的投影，并用真实已关闭轮次检验三个完整候选的绑定。本次没有据旧夹具推断调度成功率。
- 本轮未新训参考解、未生成新整网性能成绩，也未运行多轮或完整 L3。完整的新版多轮行为、跨 ViT 的决策稳定性、不同 Skill 的增量作用，以及官方 90% 目标均留待真实科研验证。[当前伪代码](PSEUDOCODE.md)
