# gonly 研究与冻结增量的执行顺序

`HEAD fad4657` 上的本轮工作区。研究动作由 Generation 选择。下列分支是可用入口，例示的搜索和诊断次数由具体问题决定。[工程入口](../../../QAViT/docs/CAPABILITIES.md)

```text
从本轮任务的可见版本恢复 Brief、已绑定任务、独立 B、完整父方案和活动主题
构建本次材料
    直达当前问题、确切状态、最近的配对结果及适用条件
    合并同一正文，已省略页留下版本、位置、读取方式和失败状态
    Generation 可按需精读、重开旧页，或在一次请求中指明后续保留的活动材料

Generation.focus 基于可见证据决定继续、收缩、扩大、建立或切换主题
    若某个缺失观察会改变资源投入，通过已有 request_experiment 请求
    程序 Supervisor 按现有预算调度。Evaluate/worker 返回原任务的 Evidence 或失败
    Generation 权衡定位线索、合法修改响应和反证，保存选题与复议条件

Generation 在 H1/H2 保留完整父方案及弱保底，在 H3 接续已有灵感和实现
    可直接提交、提出实验、调用已有方法，或请求 Coding 实现有依据的改动
    新代码沿用原请求、Coding、Safeguard 与执行绑定链
    冻结实验载入确切 Evidence/solution/model_ref 及对应版本源码
    若需要比较候选
        Generation 声明候选池、原图视图、输出/参考、指标与比较预算
        calibration 原图用于选参。search 用于确认显式候选
        每个候选从同一完整父状态的独立实例出发，空修改直接使用原网格
        按绑定分类变换或分割任务的原图预处理、窗口顺序执行真实量化前后缀
        对每个命名观测按层、窗口和原图归约并保留明细
        按声明的目标从同一分数表提名，返回修改指纹、原图身份及 Evidence
    若 Generation 决定接受
        核对选中项、评分来源、确切父包、修改前后网格和训练来源
        在完整父状态上应用该项。沿用相应 exporter、冷载与协议校验
        任何不一致返回失败，父包继续可用
    evaluate 在绑定的开发/正式协议下对同一冻结状态测两个任务
    原任务收到实际结果和限制，决定沿子状态修订、回退或另做取证

三个最终候选继续进入既定 L3 调度
Recorder 依既有契约维护方案库、方法库、灵感库及确切来源
独立 B 和经核验的状态可再次冷载。达到何种科研结论由 Generation 判读
```
