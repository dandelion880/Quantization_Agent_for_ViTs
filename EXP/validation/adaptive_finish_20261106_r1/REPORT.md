## 实际能力与配置

保留独立单卡实验并发，以及满足能力条件的分类内部多卡。ADE/混合评测、局部探针、profiling、factory/fixture、自定义 executor、训练和必需性能指标不启用内部多卡；继续原兼容路径。默认每实验一卡。GPU 数量不影响非 Judger 单通道、Judger 最多三并发且同场有序的规则。

只需在研究 JSON 的 `runtime` 集中配置：

```json
{"allowed_gpus": "auto", "experiment_concurrency": "auto", "llm_concurrency": 4}
```

`allowed_gpus` 也可为允许的 NVML 编号或完整 GPU UUID 数组；`[]` 禁用 GPU。`experiment_concurrency` 可显式设整数。探测不可靠时可给 `gpu_inventory` 的 index/uuid/device_node 对照，并用 CUDA_VISIBLE_DEVICES 的 UUID 列表提供可见性。容器外 NVIDIA_VISIBLE_DEVICES 数字无法对应容器内编号时，使用 UUID 或显式硬件映射，不能忽略分配范围扩权。详细边界见 [EXECUTION.md](../../../QAViT/docs/EXECUTION.md)。允许池与映射冻结在 `research_run.json`，不会按主机新发现的卡扩权。运行中不热插拔扩池；恢复重新匹配冻结 UUID。

本轮未验证 MIG、跨主机或训练型内部并行；四/六卡仅做设备模拟，没有对应实体硬件。未新增真实 LLM 调用，Coding 重叠/反馈和完整科研流程本轮主要由离线回归覆盖。已有 CLI/认证预检仍沿用原入口。没有完整真实 L3、全量分类/ADE、新方法有效性或吞吐加速结论。本轮目标达到，停止继续扩大修复或启动正式科研。
