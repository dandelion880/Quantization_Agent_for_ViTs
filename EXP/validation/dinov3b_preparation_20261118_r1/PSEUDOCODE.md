# 当前 G-only 流程

完整角色、事件和恢复机制沿用[多 ViT 伪代码](../multi_vit_20261118_r1/PSEUDOCODE.md)。以下是本次改变的执行路径。

```text
基线准备（独立程序测量，无科研轮次）
    从用户绑定的原 FP 模型、任务头、完整方案与允许校准数据重建
    将原生计划交给既有 ExperimentBroker 和数值任务队列
    冻结参数并核验全网协议，导出，独立加载
    对同一重载骨干测量完整分类及冻结分割，把真实回执提交给 Journal

科研启动
    根据本次输入绑定资产、样本、协议和源码快照
    如指定准备基线，校验原 Journal、程序 L3、原始资产、训练许可、
        导出包、独立重载与两项全量测量，按原规则登记完整方案并保留 B

每轮
    Generation 恢复主题、灵感、未完成动作和复议点，决定继续或调整
    独立生成 H1、H2、H3
        H1/H2 根据完整父方案和来源作实质改良，可借用和注明灵感
        H3 延续或更换活跃灵感，按其确切源码、配置及实测发展方法
        根据当前证据质量和成本自主试验、反驳、修订或提交
        新逻辑经 Coding -> Safeguard -> 实测 -> 原 Generation
        用原生 v3 方案时可在冻结背景中 refine_frozen 并留存选参记录
    Generation 综合审查，必要时修订；宿主绑定三条确切版本并分别规划 L3
    Coding 串行；运行时优先分配不同候选，再考虑单项任务内部并行
    导出实际生效的 W/A、仿射参数及计划；比较重载状态和同图输出
    用禁止重新拟合的加载器迁移；符合全身份的分割 FP 记录可复用
    Recorder 保留条件、失败、反证、代码与配置，提出未完成动作和复议建议
    宿主记录纯数值等待、活跃预算、重试及资源，维护独立 B 并继续
```

局部实验的覆盖由其问题和冻结规格确定。正式双任务由实际输入给定；本次具体 DINO 资产与校准数量见[正式输入](../../inputs/dinov3b_static_w4a4_gonly_next4/input.json)。
